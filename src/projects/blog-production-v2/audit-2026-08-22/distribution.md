# Audit: Distribution, analytics, and the feedback loop

> Generated 2026-08-22 by a multi-agent audit of tiles/blog-production and its chain. Evidence cites working-tree file:line at audit time.

## Summary

Distribution in this system stops at drafts for every channel except YouTube. The golden sample (2026-08-19) produced excellent, platform-native copy for X, LinkedIn, Facebook, and Beehiiv, but distribution.json (lines 38-59) records all four as "pending" with blockers "no API credentials — manual post" / "no Beehiiv credentials — manual send", and no artifact anywhere records that they were ever posted. The measurement layer is more real than it looks from the prose: scripts/blog-growth.mjs is a 1,309-line, 67-test CLI with a live Turso DB holding 5,626 Rybbit rows (through 2026-08-13) and 264 YouTube Analytics rows (through 2026-08-18) for four older videos, so YouTube analytics + site analytics ingestion genuinely works. But the loop is open at both ends: the golden-sample slug is not in growth_content_items ("No content item found for slug: deepseek-harness-teardown"), its distribution.json uses keys (url/video_id/publish_date) the registrar does not read so a dry-run registers three posts with null IDs, only one AI postmortem review has ever been written (2026-06-20), growth_content_evaluations has 0 rows despite the 07-01 run doc claiming one, and all 12 postmortem.md files across 19 packages have empty or "pending" Actual 24h/7d sections. Consequently next-brief-context has returned the same two manual July lessons plus one June review for every package since, and 08-02 and 08-19 both cite `deep_reader_signal`, `concrete-bottleneck-opening`, and `linkedin_manual_import_missing` verbatim — the "reinforcement gate" is recycling a fixed prompt, not learning. The brand-sales employee-agent has run a scheduled daily shift for 35 days and written 32 identical "awaiting_renewal" reports because its one campaign (A-001, 2026-07-17) was never approved; it closes no loop. There is no repurposing module (Shorts/clips/quote cards) for the blog film, no Chinese-platform distribution path, no automated newsletter send, and SEO is limited to frontmatter + chapters + UTM'd description. A content-catalog scan today also ran against a non-main branch of the blog repo (latest published = 2026-08-02), and the 2026-08-21 package reused post number 30 already taken by deepseek-harness-teardown on origin/main.

Each carries a distinct UTM (utm_content=launch-reply / launch-preview / launch-friends / launch-teaser) generated per tiles/blog-write/references/social-distribution.md:60.

Live DB: rybbit rows 2026-05-16..2026-08-13 (5,626), youtube rows 2026-06-14..2026-08-18 (264) for 4 videos. 67 unit tests pass. .env has TURSO_URL, TURSO_AUTH_TOKEN, RYBBIT_*, LINKEDIN_ACCESS_TOKEN set.
  - Why it matters: This is not vaporware — the hard integration work (OAuth, Rybbit API with rate-limit backoff, Turso schema with scorecard views) is done. The minimal real loop is a scheduling/wiring problem, not a build problem.
- **Distribution plan discipline with explicit measurement caveats** — src/content/blogs/2026-08-19/distribution-plan.md:37-42 (per-platform job/asset/CTA/tracked link/success metric/follow-up atom table), :44-46 (link-placement experiment kept comparable to 08-02), :64-66 (do not read missing LinkedIn data as zero). social-distribution.md:5-7 'Evidence Boundary' refuses to treat platform folklore as fact.

- **Beehiiv list capture is wired on the site** — /Users/aaronguo/Work/ag/blog/aaronguoblog/server/api/subscribe.post.ts:34 posts to api.beehiiv.com/v2/publications/{id}/subscriptions; components/newsletter/Signup.vue:44-45 calls /api/subscribe; pages/blogs/[...blog].vue:161 renders <NewsletterSignup variant="inline"/> on every article. ## Gaps

### [high/structure/S] Golden sample is invisible to the growth DB: wrong distribution.json schema and never ingested

- Evidence: src/content/blogs/2026-08-19/distribution.json:26-36 uses keys url/video_id/publish_date, but scripts/blog-growth/lib/ingest.mjs:150-162 reads only channel_post_id/channelPostId, channel_url/channelUrl, published_at/publishedAt. Dry-run register-channel-posts prints channelPostId:null, channelUrl:null, publishedAt:null for all 3 posts; ingest-youtube filters rows without channel_post_id (main.mjs:450-453). `postmortem --slug deepseek-harness-teardown --dry-run` -> 'No content item found for slug'. Compare 2026-06-15/distribution.json:4-12 which uses the correct keys. 2026-08-02/distribution.json:6 records S-cNWJhWaTU while the DB's 08-03 row is vlCfO_EjF8k — a second drift.
- Recommendation: Make distribution.json a validated schema: add a JSON schema + `blog-growth.mjs validate-distribution --file` that fails on unknown keys and missing channel_post_id/published_at, and have blog-package-quality.ts --require-release call it (it currently only checks file existence, blog-package-quality.ts:279-300). Then register + ingest the 08-19 video (5vEEBhbfUWw, published 2026-08-16) so the one package that matters has data.

### [high/measurement/M] Postmortem outcomes have never been recorded in 19 packages; the template has no forcing function

- Evidence: grep 'Actual 24h' matches 12 postmortem.md files; every one is empty or 'pending' (07-06:42-48 'Pending publication', 08-02:14-16 blank, 08-19:13-19 'pending', 09-16..10-07 'PENDING — no external publication'). DB: growth_ai_reviews has exactly 1 row (postmortem_7d, 2026-06-20); growth_content_evaluations 0 rows; growth_ingest_runs 0 rows. tiles/blog-production/templates/workflow2/postmortem.md is 15 lines of headings. package-state.json:38-40 'postmortem: pending' 5 days after publish, with no one polling it.
- Recommendation: Two forcing functions. (1) A scheduled job (launchd, like scripts/com.aaron.daily-log.plist) runs `blog-growth.mjs postmortem-fill` nightly: for every package-state.json with release.blog.status=published and postmortem.status!=complete, if now>=publish+24h (or +7d) it runs ingest-rybbit + ingest-youtube for that window, runs `postmortem --window`, and writes the numbers into postmortem.md 'Actual 24h/7d' and flips package-state.postmortem.status. (2) blog-production bootstrap (SKILL.md:93-97) refuses to start a new serious package while any published package older than 8 days has postmortem.status != '7d-recorded', unless Aaron passes an explicit --skip-postmortem with a reason written into the new package's postmortem.md.

### [high/measurement/M] next-brief-context is a frozen prompt, not a learning loop

- Evidence: DB: growth_lessons = 2 rows (both manual, 2026-07-01, from docs/blog-growth/runs/2026-07-01-feedback-loop-seed-lessons.json), growth_ai_reviews = 1 row (June). 2026-08-02/distribution-plan.md and 2026-08-19/distribution-plan.md:13-20 both cite deep_reader_signal, concrete-bottleneck-opening, single-owner-shared-boundary, linkedin_manual_import_missing. main.mjs:1196-1214 heuristicRubricScores is regex keyword matching (e.g. 'because|why' -> mechanism=4) presented as a 'prediction'. buildPostmortemReview (ingest.mjs:347-427) emits only 3 canned insight labels.
- Recommendation: Stop calling it a reinforcement gate until lessons are outcome-derived. Minimum: (a) delete heuristicRubricScores and require --scores from the editorial-scorecard.md the workflow already produces; (b) make buildPostmortemReview compare prediction vs actual (prediction row must exist or it errors) and emit a lesson only when a metric beats/misses the previous 3 packages' median; (c) expire lessons after N packages unless re-confirmed; (d) show in the completion report how many packages have real 7d data so the sparsity is visible.

### [high/automation/L] Distribution execution is manual for X, LinkedIn, Facebook, and newsletter; no posting automation exists

- Evidence: 2026-08-19/distribution.json:38-59 pending blockers: LinkedIn 'stored token lacks w_member_social', X 'no API credentials', Facebook 'no API credentials', newsletter 'no Beehiiv credentials — manual send'. grep for posting code (w_member_social, api.x.com, ugcPosts, rest/posts) hits only lib/linkedin.mjs analytics and yt-publish SKILL. yt-publish/SKILL.md:159 suggests a non-existent /baoyu-post-to-x. .env has LINKEDIN_CLIENT_ID/SECRET but no X keys; blog repo .env has BEEHIIV_API_KEY + PUBLICATION_ID unused by the studio. No record of whether the 08-19 social drafts were ever posted.
- Recommendation: Realistic path per channel: LinkedIn — re-auth the existing app with w_member_social (Share on LinkedIn product, free) and add `blog-growth.mjs post-linkedin --file linkedin-brief.md` using /rest/posts; it returns the share URN that distribution.json needs. Beehiiv — `post-newsletter` via POST /v2/publications/{id}/posts using the existing key (Beehiiv API is on paid Scale/Max plans; confirm plan). X — Free tier of the X API allows ~1,500 writes/month for POST /2/tweets at $0; enough for launch+reply+standalone; store keys in .env. Facebook — personal-profile posting is not available via Graph API (Pages only); keep manual but add a `record-post --channel facebook --url` that writes the post URL into distribution.json. Each poster must append the returned ID/URL to distribution.json in the schema the registrar reads, then call register-channel-posts.

### [medium/automation/S] Brand-sales employee-agent is 35 days of no-ops

A daily agent that reads the whole contract and writes 'nothing happened' is token spend with negative signal-to-noise. If renewed, its charter should be 'close the loop' (ingest, register, fill postmortems, flag drift) before 'publish'.
