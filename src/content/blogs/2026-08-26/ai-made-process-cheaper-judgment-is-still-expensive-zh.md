# AI 让流程变便宜了，但判断力依然昂贵

三名工程师，五个月，大约一百万行代码，1,500 个 pull request，没有一行代码由人直接写入。

这是 [OpenAI 公布的一组数字](https://openai.com/index/harness-engineering)。他们用 Codex 做了一个内部产品，并估算整个开发过程只用了人工编写代码所需时间的十分之一。

但真正值得注意的不是那一百万行代码，也不是“零人工写码”。更重要的是团队如何组织这些工作：他们从项目初期就引入了很多公司通常等到数百名工程师时才会建立的架构约束。依赖方向、定制 linter、结构测试、仓库内知识和反馈环，都不是产品成熟后的治理补丁，而是 agent 能够稳定工作的前提。

执行变便宜以后，结构反而被提前了。

我刚刚在另一个完全不同的项目里看到同样的变化。[DeepSeek Harness](/blogs/deepseek-harness-teardown) 在 64 天里积累了 12,293 次提交。它的背后是 683 篇决策记录、一系列机器 gate、文档预算、冻结的历史推理，以及必须以可执行检查收尾的 postmortem。项目第二天的一篇流程记录已经把原则写得很直白：agent 遵守强制 gate，远比遵守文字约定可靠；当工作由 agent 完成时，“工作量太大”不再是一个充分的成本理由。

两个独立的 agent-native 系统走向了同一个结论：AI 没有消灭流程，它改变了流程的经济学。

好的流程开始变成一种组织资本。一次判断可能很贵，但一旦写进系统，就能低成本地作用于之后成千上万次执行。稀缺资源因此向上移动：哪些判断值得编码，哪些例外必须交还给人，哪些旧规则已经不再值得维护。

## 执行变便宜，结构就会前移

传统软件流程围绕稀缺的执行能力设计。写代码需要时间，测试需要时间，文档会挤占交付。每增加一条规则，就意味着已经在做事的同一批人多承担一项义务。

所以，“这套流程太重了”过去是一个成立的经济判断。每个重要改动都写设计记录，的确能改善组织记忆，但也可能把负责交付的团队拖垮。架构治理、定制检查和完整的决策档案，往往要等组织足够大、付得起这笔成本以后才出现。

Agent 削弱了这个取舍。它可以实现功能、补测试、更新设计记录、审查 diff，再修复失败的检查。一条规则写进系统以后，不需要再开一次会，就能以机器速度重复执行。执行流程的边际成本，正在和生成代码的边际成本一起下降。

OpenAI 的实验把这种变化表现得很清楚。他们不是简单地把 Codex 当作更快的程序员，而是重新设计仓库，让 agent 能理解业务领域、启动应用、检查日志和指标、操作界面、审查自己的改动，并从失败中恢复。约束之所以产生杠杆，是因为 agent 能直接读取并执行它们。

这也是 DeepSeek Harness 改变我看法的地方。我原本进入仓库，是想找一些巧妙的 agent 架构。后来我花了几天，用十四个分析 agent 追踪代码，并逐一核对数百条源码级结论。代码当然有意思，但代码周围的运行系统更重要。

它会保存被否决方案背后的 reasoning，让未来的 agent 必须击败旧理由，而不是无意间重新发起同一场讨论。它把过时历史移出默认搜索，避免旧事实在检索结果里盖过当前规则。它要求 postmortem 产出新的 verifier 或测试，并通过恢复原 bug，证明这项保护真的会变红。

这些文档、测试和历史不只是工作的记录。它们已经进入生产系统本身。

## Harness 是可以执行的组织资本

经济学里有一个很适合解释这件事的概念。通用技术很少只靠技术本身释放全部价值。在 [*The Productivity J-Curve*](https://www.aeaweb.org/articles?id=10.1257/mac.20180386) 中，Erik Brynjolfsson、Daniel Rock 和 Chad Syverson 讨论了 AI 等通用技术周围必不可少的互补投资：新的流程、产品、商业模式和人的能力。

这些投入一开始看起来更像成本，而不是产出。企业买到了新的技术能力，却必须先重新设计工作如何流动，生产率才会真正出现。其中很大一部分属于无形的组织资本——资产真实存在，却很难被传统财务报表完整识别。

Harness 就是这种组织资本的可执行形态。

这里所说的 harness，不只是一个 prompt 或一组工具，而是 agent 周围的运行与约束系统。它告诉 agent：组织知道什么，可以使用哪些工具，必须遵守哪些边界，什么证据才算完成，以及什么时候必须把决定交还给人。

这个定义比 prompt 更宽，也比工具清单更有用。Prompt 表达一次运行的意图；harness 则让组织判断跨越多次运行继续存在。Context 如何组装、权限如何控制、skills 如何复用、结果如何评估、历史如何保存、失败如何恢复，都属于这个系统。

这也改变了企业投资 AI 时应该问的问题。模型能力是租来的：竞争对手同样可以买一个订阅，或者调用同一个 API。围绕模型积累下来的验收标准、评估集、运行规则、决策历史和恢复路径，却留在组织内部。前者是不断发生的投入成本，后者有机会成为提高每次未来运行回报率的自有资产。

如果把 AI adoption 理解成给员工购买工具，结果很容易令人失望。[DORA 2025 报告](https://dora.dev/research/2025/dora-report/) 把 AI 描述为组织现有优点和弱点的放大器。把 agent 放进边界清晰、反馈充分的系统，它会放大这套系统；把同一个 agent 放进所有权模糊、知识分散、证据薄弱的组织，它只会更快地产生更多模糊结果。

模型是生产函数的一部分，但不是完整的生产函数。

当然，本文引用的案例都位于前沿：OpenAI 团队在描述自己的内部产品，Anthropic 在分析自己的产品数据，DeepSeek Harness 也是一个年轻且 agent 吞吐量异常高的仓库。它们不能证明每家公司投资 harness 都会得到同样回报。它们的价值更窄，也更可靠：不同实现都提前暴露了同一种瓶颈迁移。

## 工作没有消失，而是从执行移向判断

当执行成本下降，剩余工作的形状会变得更清楚。

[Anthropic 分析了大约 40 万次 Claude Code 会话](https://www.anthropic.com/research/claude-code-expertise)，时间跨度从 2025 年 10 月到 2026 年 4 月。在典型会话中，人做出了大约 70% 的规划决策，却只做出了约 20% 的执行决策。人主要决定做什么、选择哪条路线、什么算完成；Claude 主要决定改哪些文件、写什么代码、运行哪些命令。

同一项研究还发现，任务领域知识依然重要。对业务和问题理解更深的人，更容易得到可验证的结果；任务出错时也更容易恢复；一条指令能够触发的有效 agent 工作也更多。

这是早期的观察数据，而且来自厂商自己的产品，不能当作永远不变的劳动定律。未来的模型可能承担更多规划工作。但它至少清楚地揭示了当前分工：AI 先扩大了判断的执行半径，还没有消除判断本身。

人的贡献向上移动了一层。人不再决定每一行代码怎么写，而是选择目标、定义验收边界、解决取舍，并发现现有测试还不知道如何描述的失败。当同一种情况不断出现，人再把这个判断下沉到 harness，变成规则、评估、skill 或工具。

这会形成一个复利循环：

```text
人的判断
   ↓
写进约束和反馈系统
   ↓
agent 低成本规模执行
   ↓
暴露新证据和例外
   ↓
人修正原有判断
```

这个循环不会自动完成自我提升。仍然需要人发现真正重要的失败，判断它是否具有普遍性，再决定系统应该修改什么。它的价值在于，人的参与会留下资产。下一次运行从更高的基线开始，而不是让另一个人重新发现同一条教训。

我在七月写过 [The One-Person Project](/blogs/one-person-project-ai-coding)：一个明确的责任人持有一个有限项目的完整 context，agent 扩大他的执行半径，团队则共同拥有边界和证据。Harness engineering 是同一个思路在系统层面的展开。系统能更广泛地使用一个人的判断，所以这个判断本身也变得更有价值。

## 廉价流程也能制造昂贵的垃圾

这个观点有一个明显风险：既然 agent 能廉价生成测试、文档和规则，团队同样可以制造出一大片没有人真正理解的流程森林。

两个主案例都包含这个警告。

OpenAI 团队提到，高自治 agent 会复制仓库里已有的模式，包括不够好的模式。有一段时间，他们每周五都要清理 “AI slop”，相当于花掉一周 20% 的时间。后来，团队把一小组首选模式写进系统，让后台 agent 持续发现并修复偏差。人工清理赶不上生成速度，所以清理本身也必须系统化。

DeepSeek Harness 有一个更尖锐的反例。一次真实 Loader 入口错误，逃过了 178 个绿色测试和 100% 的行覆盖。测试是手工挂载插件的，从未经过产品真正使用的入口。所有检查都通过了，因为那个缺失的问题从未进入检查系统。

这起事故划清了文章的边界。一个 gate 并不包含普遍判断，它只包含作者针对某个已知世界成功写下的一项判断。未知路径、变化中的条件和错误假设，依然可能落在它的视野之外。

规则本身也有维护成本。DeepSeek 的决策记录有明确的 implemented、rejected 和 archived 状态，但它的 gate 没有同样清晰的退役系统。每一次事故都可能增加一个 verifier、一张例外清单，以及一个未来贡献者必须理解的新概念。单独看都合理的保护，积累起来也会成为组织阻力。

所以，普通团队不应该照搬 AI 实验室或一个 12,000 次提交项目的流程密度。真正值得吸收的不是“增加 gate”，而是重新计算哪些 gate 现在值得购买。小团队需要编码的判断应该更少，每一条的门槛应该更高。

AI 让好流程变便宜，也让坏流程更容易膨胀。

## 流程资本三问

现在，当我考虑是否增加一条规则、评估、skill 或决策记录时，会先问三个问题。

### 1. 它是否捕捉了一个反复出现、代价高昂的判断？

有价值的约束，要么防止一个很可能再次发生的错误，要么消除一项持续占用稀缺注意力的决定。一个因为测试绕过真实入口而逃逸的生产事故，值得被编码。一个 agent 不断重新提出的架构方案，也可能值得保存否决理由。某位 reviewer 的个人代码风格偏好，通常不值得。

如果底层判断很少发生、代价很低，或者高度依赖具体情境，那么编码它可能比再次判断更贵。这就是官僚化：流程被保存了，真正有价值的东西却没有。

### 2. 系统能否应用它、检查它，或者主动暴露例外？

规则需要一个实际运行路径。结构约束可以变成 linter；质量要求可以变成带可见证据的评估；被否决的决定可以保存在 agent 提案前会搜索的位置；生产预期可以变成指标或验收测试。对于无法安全自动化的决定，系统至少可以主动收集相关证据，把例外交给正确的责任人。

如果每次应用仍然要求人阅读一篇长文，再临场解释规则的意思，组织并没有减少判断成本，只是把人工劳动藏在了一个新 artifact 后面。

这个逻辑并不限于软件。财务团队可以把对账容差、证据要求和升级阈值写进系统，让 agent 先准备关账材料并隔离异常。Agent 负责重复检查，controller 仍然判断一个异常差异究竟来自数据错误、真实业务事件，还是一条应该修改的旧规则。

并不是每个重要决定都应该机械化。产品方向、客户取舍和架构例外往往必须由人解释。关键是主动把它们分开，而不是用一大堆检查制造虚假的确定感。

### 3. 谁负责它的折旧？

组织资本会老化。模型会进步，产品会变化，昨天防止事故的规则也可能变成明天的障碍。

每一条长期规则都需要明确的人，或者至少一套固定流程，负责修改、合并或删除它。决策记录应该说明什么证据可以推翻它；gate 应该保留一个未来维护者能理解的存在理由；skill 应该用当前行为验证，而不是因为曾经有用就永久保留。如果一条规则制造的例外、解释和绕行工作，已经超过它减少的重复判断，它就在折旧。

没有责任人，也没有退役条件，流程最终会变成制度化石：仍然清晰可见，仍然昂贵，却已经失去生命。

这三个问题的门槛是刻意设置得很高。第一问失败，会产生官僚化；第二问失败，会留下隐藏的人工劳动；第三问失败，会制造化石。全部通过也不能保证规则一定正确，但至少说明了这笔投入原本应该换回什么。

## 管理工作正在移向判断层

第一波 AI adoption 主要竞争工具入口：哪一个模型、哪一种订阅、哪一个 coding agent。下一阶段的差异会更多来自入口周围的系统。

这不意味着 instruction file 最长的公司会赢。真正的能力，是把重复经验转成更好的边界、证据和反馈，同时不让过期规则埋葬整个组织。同一份底层模型能力，因此可以产生完全不同的经营结果。

管理者的问题也要随之改变。除了问“agent 能完成多少工作”，还要问：“我们有哪些判断，值得通过系统持续复利？”

最值得观察的地方，是 review 反复停住的地方。如果不同运行总是遇到同一种模糊、修正或风险判断，它就是进入 harness 的候选项。如果一条旧规则不断产生例外，需要的解释已经超过节省的判断，它就是删除的候选项。目标不是把流程做到最大，而是让重复判断下沉，把人的注意力留给真正的新问题。

随着判断逐渐清晰、可以重复，一部分会向下进入系统；当系统遇到看不见的新例外，决定又会向上回到人。Harness 正是这两种移动之间的接口。

DeepSeek Harness 让这个接口变得异常清楚。OpenAI 的实验展示了同样的经济学如何出现在一个真实使用的产品中。Anthropic 的数据则揭示了当前的人机分工。它们都不能证明人的判断会永远稀缺，但它们共同说明：只增加 agent 劳动力，却不投资周围的组织系统，是一套不完整的生产策略。

操作规则很简单：如果 review 总是在同一个决定上停下，就把它编码；如果一条规则制造的例外比它消除的例外更多，就把它退役。用 agent 扩大执行，但把人的判断留在“什么应该重复、什么必须保持开放”的边界上。

AI 让流程变便宜了。机会在于把正确的流程变成资本，纪律在于删除其余部分。
