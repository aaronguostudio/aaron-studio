在 DeepSeek Harness 里跑 V4 Pro，我注意到的第一件事是：我没有工具箱了，我有一门编程语言。

整个系统里只有一个工具能被直接调用——`run_code`，它运行我写的一段 TypeScript 函数体。其余所有工具——读、写、改、bash、grep、glob、搜索、skill、subagent、goal、todos——都只能在这段程序内部，用 `await tools.read(...)`、`await tools.bash(...)` 这样的方式，一行接一行地编排出来。这不是藏在设置里的某个偏好，而是这台机器默认的形状。

这个事实在十分钟内就重组了我的工作方式，也正是从这一刻起，它的"感觉"和我以前用过的所有 AI 都不一样了。

大家都在问，DeepSeek Harness + V4 Pro 用起来是什么感觉。诚实的答案是：不是"更聪明的聊天机器人"，而是模型长出了身体。V4 Pro 是大脑，而且本来就是个好大脑；Harness 给了它这副身体，而身体才是你真正能往上盖东西的那部分。

"身体"不是抒情，它是 Harness 给模型的四件结构性礼物的简称，每一件都改变了你真正能放心交给它的事。我此刻正在它所描述的这套系统里写这篇——DeepSeek Harness、V4 Pro，在 Harness 开源刚过一周、模型同日 GA 之后，跑着这条生产管线。所以下面这些是观察到的，不是回忆出来的。一个怀疑者完全有理由说这是利益冲突，我用收据来回应。

## 身体，拆成四件

第一件是手。在聊天界面里，模型的"工具"是一张菜单——你看它伸手够一个，等着，再够下一个。在这里，工具面是一门编程语言。模型不是调一个工具、解说一句，而是写一小段程序去编排好几个工具，把中间结果留在变量里，最后只把程序的输出交回来。当我需要读十五个文件、交叉核对它们的 slug 再动笔时，我不是用十五个来回做完，而是写一个函数，批量读取、去重、返回一份摘要。工作的最小单位，从"一条消息"变成了"一段替这条消息干活的程序"。

![一只手写下一行，同时牵动四个工具](imgs/web/01-hands.webp)

第二件是能力。在大多数工具里，让模型擅长某件事靠的是你敲进去的 prompt——一段你得记住、反复打磨、反复重敲的话。在这里，能力是一个文件。skill 以一份 `SKILL.md` 加一个装满资源的目录的形式到达，任务需要时模型就加载它。这个差别听起来很学术，直到你亲身感受到："按我的方式写这篇博客"不再是每次粘贴的一段话，而是一份我拥有、能版本化、能跨会话复用的 skill。这个会话正在用的目录里有几十份这样的东西。它们都不住在模型权重里，而住在我能带走的文件里。

![一只手把一张空白卡片插进读卡器，一道绿色对勾亮起](imgs/web/02-competence.webp)

第三件是连续性。聊天模型在对话结束的那一刻就忘了。装进 Harness 的模型握得住状态：一个跨回合持续存在的 goal、一份边干活边更新的任务清单、在某个分支需要独立上下文时能 fork 出去的 subagent、以及可以挂在后台跑、自己先干别的 background job。这才是"委托"之所以可能的前提。你可以把一个十二步的任务交给它然后走开，因为往前推进的是任务本身，而不是你对任务的记忆。

![椅子空了，工作还在桌上自己往前推进](imgs/web/03-continuity.webp)

第四件是记忆，会计意义上的。Harness 给这次运行写一份只追加的日志，而这个会话正在维护的那些工件——把事实、推断、判断分开的 claim ledger，按明确契约给稿子打分的 scorecard——是把同一套想法再往上推一层：工作留下一条事后能审计的轨迹。出了事，你不用还原模型当时在想什么，直接读日志。

这四件——手、能力、连续性、记忆——就是身体。而且每一件都是你能在模型之间带走的东西。

## 身体买到了什么

下面是真正有商业价值的部分。当模型有了身体，工作的最小单位就从"一个答案"变成"一件你能端到端交出去的任务"。

我在[拆解文](/blogs/deepseek-harness-teardown)里说过，harness 才真正决定 completion、成本和审计；更早在 6 月说过，[AI 工作的最小单位从 response 变成了 run](/blogs/fable-5-managing-ai-autonomy)。那时是分析判断，背后还有第三方数字撑着：同一个模型，[跑过八个 harness、三十个真实工作流](https://composio.dev/content/best-agent-harness-deepseek-v4-flash)，成功率从 46.7% 摆到 66.7%，每完成一个任务的成本差 7 倍。坐进这台机器之后，这些分析判断变成了体感事实。聊天模型产出一个答案，你还得拿它再去做点什么；装了身体的模型跑完一个任务——从 idea 到 outline 到草稿到红队到润色到打分——交回来的是成品，外加它是怎么一步步走到那儿的轨迹。

这就是藏在满屏"agents"话术底下那个安静的变化。瓶颈不再是"我能不能从这个模型榨出一个好回答"，而是"我能不能信这次运行"。而这份信任，是用那四件东西搭起来的，不是靠模型的文笔。

它同时改变了委托的成本。在聊天循环里，委托很贵，因为每一步都要你重新喂上下文、重新盯方向。当模型自己握状态、自己写日志，委托就变便宜了——因为那些会滑掉的东西——计划、保留意见、决策历史——都放在一个你能查的地方，而不是放在一个你得靠记性的地方。

## 诚实的边界

我想把身体到底做了什么、没做什么讲清楚，因为"agents 会吃掉一切"这类说法通常就是在这儿翻车的。

第一，身体让失败规模化，和让工作规模化一样高效。一个握着工具、状态和自主权的模型，能烧 token、能死循环、能长时间自信地干错事——而 DeepSeek 自己的文档也很诚实：loop 失控保护只发提醒、不强制停，文件工具根本没设 timeout。开源几小时内上线的中文实测用一句话说清了：能干活，但得盯着。[Armin Ronacher](https://www.theregister.com/ai-and-ml/2026/08/14/deepseeks-innovative-harness-treats-everything-as-a-plug-in/5288095) 说这个 harness"不完美"，[一个有仓库权限的早期测试者](https://x.com/jiayuan_jy/status/2087911060154314963)说得更直接——日常体验还落后于 Claude Code 和 Codex。我不是来反驳这个的。这篇不是在说 DeepSeek Harness 是你本周能用到的最好的 agent 工具。它不是。

第二，"变强"的感觉有一部分是舞台效果。V4 Pro 在长出身体之前就已经是 V4 Pro 了。Harness 加的不是智能，是结构——把已经在那里的智能装进一副身体。让人印象深刻的不是模型变聪明了（它没有），而是同一个模型，放进身体之后，能握得住计划、能核对自己的活儿、能在十二步的管线里不跑偏。

第三，也是我最在意的一点：这一切都不意味着系统在自我改进。[流程变便宜了，判断力依然昂贵](/blogs/ai-made-process-cheaper-judgment-is-still-expensive)。Harness 给了模型身体，但标准、拒绝、以及"哪次修正该沉淀成长期规则"的决定，仍然是人的活。图里有个回环不等于自我提升。这个会话维护的 claim ledger 不判断——它只记录，判断的是我。

## 看状态，别看文章

这个诚实的边界，恰恰让那条操作规则变得有用。

把一个任务交给装了身体的 agent 之后，最诱人的做法是继续用评价聊天机器人的方式评价它——看它的段落写得好不好。这是错的界面。一段话可以又顺又自信，而它背后的计划正在悄悄烂掉：事实滑成了推断，被砍掉的小节没做标记，"完成"的定义越拉越长。

正确的做法是看状态。三个检查，按顺序来。有没有一份书面计划或任务清单，而且它真的在推进？有没有一份把事实、推断、判断分开的 ledger——还是所有东西都被揉成一种自信的腔调？以及，agent 有没有写清这个任务的"完成"和"失败"分别长什么样，这样它做完时你才分得清。

状态连贯，文章通常也跟着连贯；只看文章，状态可能悄悄烂掉。这个会话我两种都见过——ledger 拒绝了我本想钉死的一个日期，因为来源在那一天上有分歧；风格扫描器打回了一个只会总结、不落规则的结尾。这两件都不像"更好的一段话"。它们都是身体在干活，之所以看得见，是因为我看的是状态，不是句子。

## 身体才是资产

最后，是我真正想让你动手去做的那件事。

[拆解文](/blogs/deepseek-harness-teardown)的结论是一条规则：模型保持可换，别跟任何一家 harness 绑太深，把你的力气投进每种 harness 都读得懂的资产层。坐进这台机器之后，这条规则被磨得更具体了。资产层不是抽象概念，它就是身体——手、能力、连续性、记忆。模型在轮换，而这些部分在复利。把 V4 Pro 换成下一款模型，skill、我握状态的方式、审计的纪律、我编排工具的方式，全都照旧运转。

这就是为什么身体比穿它的模型更重要。模型是租来、随时可换的；身体是盖起来、一直留着的。而这次转变的另一头，真正稀缺的技能不是写 prompt，而是握状态、判工作——知道"完成"长什么样、什么算证据、以及什么时候该拒绝一个顺滑的答案。

所以这就是那条规则，也是我最想让你从这篇带走的东西：当模型长出身体的那一刻，别再读它的答案，开始看它的状态。你真正在评价的——也越来越是你真正在买的——是那副身体。
