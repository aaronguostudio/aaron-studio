# 论证备忘录 · 完整重写

主张：实现成本下降，让工程师更有条件把理解需求、产品取舍和完整交付连接起来。作者建议把未来几年的成长投入客户、业务与结果。

论证起点：作者多年前在 Amazon 已判断岗位规模不必然对应相同比例的客户价值；因而后来看到组织调整和裁员并不惊讶。公开公司说明佐证其讨论对象，不能替个人判断证明所有裁员原因。

为什么是现在：实现与原型成本变化，使工程师理解到的需求更有机会被测试，也让同一个人更有条件跟进完整工作。懂业务并非新观念，可实践范围和时间分配正在变化。

章节作用：行业积累背景；客户沟通校准需求；原型比较练习取舍；商业验证考察采用与付费成本；完整交付观察实际结果。每节有不同决定及实践起点，不按嘉宾列章节。

材料：Amazon 三份说明；Boris 的 AI 编码与人工检查；Simon 的三种原型、真人验证主张及成本取舍；Kent 的完整业务责任；Microsoft 团队提速未随个人提速的自述；Ritchie 的有限历史线索。个人报表一句；单据工具明确是假设。
