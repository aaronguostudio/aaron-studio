# 写作提纲

作者：Aaron Guo。中文约 3,000–4,000 字；英文约 1,400–1,900 词。

开头：假设收到“导出 Excel”需求，agent 很快能实现；想知道的是导出后人还在做什么。
主论点：实现降价，机会前移到问题选择与需求理解。
来源引入：Boris 的个人工作方式须连同 review 限定；其余来源进入对应建议。
历史：只保留帮助理解当下的一段，不展开编程语言史。

1. 走近真实工作：观察功能背后的流程，不凭“需求工单”猜。
2. 把结果说清：正常行为、边界与验收；Microsoft 实践作旁证。
3. 用原型求证：先查最关键的不确定；Simon + 假设实例。
4. 交付整件事：从个人报表链路讲到需求、环境和返回结果。
5. 拿证据讲质量：工程知识落实成实际行为验证；Kent 的业务复杂性提醒。
6. 重看小需求：成本变化使部分被搁置的事情值得重估，不无限造软件。

结束：回收开头，工程师的注意力可以从实现难度延伸到他人工作为什么困难；写出作者愿意走向这些问题的态度。结尾不可只停在第 6 条建议。
