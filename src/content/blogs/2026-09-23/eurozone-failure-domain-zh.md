2009 年末，希腊发现的不是一个小小的会计错误。

它发现的是：所有人此前用来判断这个国家财政状况的数字，已经很难再被信任。

2009 年财政 deficit 的估计先后从 12.5% GDP 上升到 13.6%，最终来到 15.4%。[IMF 的回顾材料](https://www.elibrary.imf.org/view/journals/002/2013/156/article-A001-en.xml)记录了修订规模，也解释了为什么会变：政府部门口径扩大、欠款、国有实体和新增信息，共同改变了原来的图景。

15% 本身已经很可怕。但更危险的事情是，投资者不得不问一个 spreadsheet 无法独自回答的问题：如果以前的数字是错的，为什么下一个数字值得相信？

财政问题从这里变成了一个系统问题。

## 一个国家得先能 refinance，才有机会恢复

政府通常不会从一大堆现金里偿还每一笔到期债券。旧债到期，发行新债，用新的资金偿还旧债。这个过程叫 refinancing，而它依赖 confidence。

当 confidence 断掉，这个循环会朝错误的方向转。

财政数据被修订。投资者要求更高收益率，或者不再愿意放贷。refinancing 变贵。财政位置进一步变差。default risk 上升。confidence 再次下降。

这就是用最普通的话解释的 sovereign debt doom loop。它不意味着每一个 deficit 很高的国家都会 default。它意味着 trust 不是一个软性的、事后的感受；它本身就是融资机制的一部分。

到 2010 年 5 月，希腊进入了一个约 €110bn 的项目：约 €80bn 来自欧元区双边贷款，€30bn 来自 IMF。[IMF 的项目文件](https://www.imf.org/external/pubs/ft/scr/2010/cr10110.pdf)把规模写得很清楚。最初关于财政报告的问题，这时已经和银行风险、欧洲传染、税收、支出、增长、外部条件的正当性缠在了一起。

难题不再只是“希腊能不能还钱”，而是“如果它不能，谁拥有这个 failure？”

## 欧元是一个共享 runtime

这里的 software 类比有用，但要保持克制。

Eurozone 共享 currency 和中央货币系统，却没有完整共享公共债务、税收、国家预算、政治问责，或者“一个国家的纳税人自然承担另一个国家财政损失”这种默认承诺。

希腊在 2001 年采用欧元，Bank of Greece 同时成为 Eurosystem 的一部分。[ECB 当年的公告](https://www.ecb.europa.eu/press/pr/date/2001/html/pr010102.en.html)提醒我们，这不只是换了一个名字。货币政策进入了共享层，而很多财政选择及其民主后果仍停留在国家层。

在 happy path 上，这个安排可以很优雅。共享货币降低摩擦；共同的货币系统可以带来稳定和规模；各国仍保有自己的政治和财政选择。

但故障会把接缝显露出来。

如果希腊无法 refinance，谁该承担损失？希腊纳税人？欧洲其他国家的纳税人？ECB？持有债务的欧洲银行？曾经监督规则的机构？没有一个答案只是经济问题。每一个答案都在分配痛苦、权力和政治正当性。

所以 bailout 的争论才会这么尖锐。救助会带来 moral hazard：如果每一次失败都由别处吸收，下一次谁还有动力做得更好？但拒绝支持又可能把恐惧扩散到远不止希腊的银行和主权债市场。

救助很危险。不救，可能更危险。

## 有 backstop，不等于能自己控制它

因为希腊不能印自己的货币，很容易有人说它“没有 lender of last resort”。这说得太粗。

Eurosystem 确实有 lender-of-last-resort 功能，[ECB 的解释在这里](https://www.ecb.europa.eu/ecb-and-you/explainers/tell-me-more/html/what-is-a-lender-of-last-resort.en.html)。更准确的说法是：希腊不能像拥有独立货币的国家那样，单独支配一个国家级 monetary backstop。权力、collateral、规则和政治条件，都在一个更大的机构里。

2015 年 6 月，这一点变得非常具体。在 referendum 决定和 adjustment programme 未获延期后，ECB 把希腊银行的 emergency liquidity assistance 上限维持在 6 月 26 日水平。[6 月 28 日的公告](https://www.ecb.europa.eu/press/pr/date/2015/html/pr150628.en.html)写得很直接。ECB 年报也记录，希腊政府在广泛的流动性外流中实施了 bank holiday。

这不是说某一个机构随意按了按钮，就造成了所有结果。重点是，国家危机正在穿过一个共享系统，而紧急控制权不在正在恐慌的国家手里。

## 一个国家在削减，ratio 仍可能变坏

项目带来了支出削减、税制变化、养老金改革、公共部门调整和私有化要求。Austerity 成了这些变化进入日常生活的统称。

说 austerity 单独造成了希腊的大衰退，不诚实。希腊进入危机前，本就有严重的财政、外部、制度和竞争力问题。但只说“这个国家需要调整”，然后停在这里，也回避了算术。

Debt/GDP 有一个 denominator。

当需求下降、失业上升、企业关闭、GDP 收缩，denominator 也在变小。即使债务本身正在被处理，ratio 也可能恶化。IMF 后来的 review 承认，财政调整的规模极大，而收缩期的债务动态非常困难。[材料在这里](https://www.elibrary.imf.org/view/journals/002/2017/044/article-A001-en.xml)。

这就是从内部感受一个 failure domain：每一个修复动作都会改变系统的另一部分。保护一个边界的方案，可能会加大另一处的压力。

## Agent 在需要更多 autonomy 之前，先需要一份 failure contract

大多数 agent demo 仍然从 capability 开始：它能搜索、写作、调用工具、更新数据、发邮件，也许还能 deploy。

希腊的故事让我先问另一个问题：它错了以后会发生什么？

对于能做出后果性动作的 agent，我希望 production access 之前就有一份 failure-domain contract：

1. **Trigger：** 什么状态算 failure 或 unsafe？
2. **Owner：** 哪个可问责的人或团队拥有 incident？
3. **Authority：** 谁能 pause、override 或 escalation？
4. **Cost bearer：** 谁承担时间、金钱、客户伤害或 compute cost？
5. **Containment：** blast radius 是什么，如何限制？
6. **Recovery：** 哪些东西可以 rollback、repair 或 restore？
7. **Learning：** 什么证据会改变下一次 run、policy 或 evaluation？

这不是在聪明部分结束后附加的 bureaucracy。只要 action 会带来后果，它就是聪明部分本身。

一个共享 agent platform 在每一次 tool call 都成功时，看起来可以非常漂亮。真正的 architecture 会在这些时候显形：一个工具写错了记录，一笔付款去了不该去的地方，一个 deploy 伤到 production，或者 agent 在世界已经变化后还很自信地继续。

Happy path 决定性能。Failure mode 决定架构。
