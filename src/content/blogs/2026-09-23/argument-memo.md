# 论证备忘录

## 核心论点

系统不只由一切正常时的表现定义；它由故障来临时谁能行动、谁承担成本、如何恢复来定义。

## 为什么现在值得写

Agent 从单次回答进入共享工具与生产权限后，failure handling 的缺口比能力缺口更危险。

## 机制解释

数据可信度破裂使融资成本上升；货币共享而财政/问责不完全共享，让 bailout 与不 bailout 都有系统后果。Happy path 掩盖了 failure-domain owner 的缺失。

## 证据地图

IMF deficit 修订 → €110bn programme → 货币联盟结构 → 2015 ELA/bank holiday → austerity 及 recession 的边界。

## 需要承认的反方观点

危机时的模糊和临时协调可以保留弹性；预先写死所有规则也可能制造僵化。

## 对反方的回应

可保留裁量，但不能把 owner、authority、funding 和 recovery 留到系统已经失控才决定。

## 可复用框架

**Failure-domain contract：trigger, owner, authority, cost bearer, containment, recovery, learning。**

## 对读者的启发

任何可写、可花钱、可发布的 agent 都应在进入生产前拥有这份 contract。
