# 论证备忘录

## 核心论点

Harness——而不是模型——已经成为决定 AI 工作能否完成的那一层：同一个模型换 harness，成功率差 20 个百分点、每完成任务的成本差 7 倍；而 DeepSeek 把自己的 harness 以 MIT 开源、逐字采用对手的文件格式、把对手产品挂成自己的子节点，说明模型公司已经不敢把这一层留给别人。对个人 builder 的推论是反直觉的：厂商越是争夺 harness，你越不该把资产沉淀在 harness 里——模型是租的，harness 会动荡，唯一该持有的是 skills、指令文件和证据回路。

（这句话足够具体、可以被反驳：有人会说 harness 差异是 benchmark 噪声，或者说 harness 层会快速整合、"动荡"是暂时的。备忘录后面正面处理。）

## 为什么现在值得写

- 2026-08-11：Composio 发布同模型 8 harness 对照实验（C1-C4），第一次给"harness 有多重要"配上可引用的数字。
- 2026-08-13：DeepSeek 开源 dsh（MIT），与 V4-Pro GA 同日（C5）——两天之内，"harness 层很重要"从实验结论变成厂商用真金白银投票的战略事实。
- 英文世界目前只有 news 级覆盖；带仓库逐条验证的 operator 级分析还没有人写。时效窗口在收窄。
- Aaron 在 7 月 6 日已发表 deployment-capability 论点（"Expensive Tokens Won't Save Enterprise AI"），这是五周后落地的确认证据——连续性是真实的，不是蹭热点。

## 机制解释

为什么 harness 影响这么大？模型输出的是 token，工作的完成靠的是 token 之外的一切：上下文如何组装（哪些历史、哪些工具说明进入请求）、工具如何暴露和执行、权限和恢复如何处理、循环何时继续何时停、证据如何回流。这些全部由 harness 决定。同一个模型在不同 harness 里看到的世界不同，能做的动作不同，所以结果不同——Composio 的 7 个翻盘任务就是这个机制的直接观测（C4）。

为什么模型公司要下场？任务失败时用户分不清是模型的锅还是脚手架的锅，"我的模型好不好用"有一半握在 harness 手里。Anthropic 的答案是闭源 harness 当模型护城河；DeepSeek 的答案是反向的——MIT 开源 + 兼容对手生态，把 harness 商品化，降低自家 token 的落地摩擦（C12 事实部分 + C13，标注为 Aaron 的读法）。镜像本身就是"这一层已成兵家必争之地"的证明。

为什么结论是"own your skills"？DSH 的三个可验证选择（C7-C9）共同指向：skills、指令文件（AGENTS.md/CLAUDE.md）、hooks 这些用户资产正在变成跨 harness 可携带的通用格式——每个 harness 都读同一套文件。资产的可携带性决定了它值不值得持有。

## 需要承认的反方观点

1. **benchmark 噪声论**：30 个任务、一个模型家族、Pi 用了不同 reasoning 设置和双 provider、Prime 被剔 6 次——排名不可信。
2. **DSH 很糙论**：内测开发者 JY 直言体验不如 Claude Code/Codex；README 全大写警告破坏性变更；插件生态刚起步质量参差。
3. **快速整合论**：harness 层可能像早年的 JS 框架战一样两三年内收敛到一两家，"harness 会动荡"是短期现象，据此调整资产策略是过度反应。
4. **与我无关论**：普通 builder 用好 Claude Code 就行，这层战争是厂商的事。

## 对反方的回应

1. 承认排名不可信，本文只取"分布宽"这个对方法学缺口稳健的信号——就算 Pi 的成绩全部作废，剩下 7 个 harness 之间的差距依然大到不能忽略；另有 arXiv 2605.23950 呼应"评测必须披露 harness"（引用前核对摘要）。
2. 完全接受，而且这恰恰支持论点：DSH 今天糙，正说明 harness 层处于快速变动期——这是"churn"判断的证据，不是反例。文中明说：今天要干活，Claude Code 仍是更好的工具；本文谈的是层的移动方向，不是本周该换什么工具。
3. 部分接受：整合可能发生，但整合期的赢家未知，恰恰是"别把资产深沉淀在任何一家 harness"的理由；而 skills/指令文件已经在跨厂商标准化（C7 是 DeepSeek 单方面向对手格式靠拢的实证），持有它们在整合的任何结局下都不亏——这是免疫于结局的策略。
4. "你可以不换 harness，但你必须知道哪层是你的资产"——不关心这层的人，会把两年的 prompt/skill/工作流积累绑死在一个订阅上。

## 可复用框架

**Rent / Churn / Own 三层资产测试**：

- **Rent the model**（租模型）：模型按设计就是可换的，别和它结婚——任何把工作流焊死在单一模型上的做法都在为厂商的定价权打工。
- **Expect the harness to churn**（预期 harness 动荡）：投入使用技能，别投入深度定制；harness 大战未分胜负前，深度定制是给别人的沉没成本。
- **Own your skills and evidence**（持有技能与证据）：skills、指令文件、评估集、反馈回路——每个 harness 都读的那一层，也是唯一为你复利的那一层。

框架必须落在结尾，文章收在框架上而不是收在对 DeepSeek 的评价上。

## 对读者的启发

读者走出文章时应该带走三个变化：(1) 下次 agent 失败时，会先问"哪一层的问题"而不是直接怪模型或换订阅；(2) 看懂 8 月 13 日这类新闻的方法——不看功能列表，看厂商把哪一层商品化、把哪一层留作护城河；(3) 一个当天可执行的动作：盘点自己的 AI 资产，把可携带的（skills、AGENTS.md、评估集）和被锁定的（某家 harness 的专有配置）分开列一遍——这份清单就是你在这场战争里的仓位。
