# Harness 才是产品

Agent 把任务搞砸的时候，人的第一反应是怪模型。我自己就干过不止一次：盯着一次失败的运行，得出"模型不够聪明"的结论，然后开始琢磨要不要换一家订阅。

[Composio](https://composio.dev/content/best-agent-harness-deepseek-v4-flash) 刚发布的一组数字说明，这个反应有多大概率怪错了层。8 月 11 日，他们把同一个模型——DeepSeek V4-Flash——放进八个不同的 agent harness，跑三十个真实的 SaaS 工作流。240 次运行，判分靠程序直接检查各个应用里的实际状态，而不是让另一个 LLM 打印象分。结果：成功率从 46.7% 到 66.7%，只取决于用哪个 harness；每完成一个任务的成本从 $0.028 到 $0.195，差七倍。[三十个任务里有七个](https://x.com/composio/status/2085330850300797394)，成败完全由 harness 决定。模型一个字没改。

两天之后，DeepSeek 把自己的 harness 以 MIT 协议开源——同一天，V4-Pro 正式 GA。这两件事放在一起读，其实是同一个故事：harness 才是产品，而做模型的公司已经决定，这一层不能再留给别人。

## 七个任务翻盘，没人动过模型

在往下推论之前，先把 Composio 这组数字的局限老实交代一遍。这是一次单一 benchmark：三十个任务、一个模型家族、每次运行 900 秒上限。Composio 自己列出了这些局限——成绩最好的那家用了不同的 reasoning 设置和两个模型供应商，另一家有六次运行因为难以判分被剔除。如果你把他们的表当排行榜读，就读过头了。

但"分布很宽"这个信号扛得住所有缺口。把冠军整个扔掉，剩下七个 harness 之间的差距，放在技术栈的任何其他一层都没人能接受：二十个百分点的成功率、数倍的成本，来自大多数团队当作可互换外壳的那一层。这不是排名结论，是存在性证明：你和模型之间的那个东西，对结果的影响不亚于模型本身。

那么问题来了：那个东西到底在干什么？

## Harness 是 operating contract 的产品化

剥掉包装，一个 harness 反复做的就是几类决定：什么东西以什么顺序进入上下文窗口；模型看到哪些工具、工具说明怎么写；什么操作需要审批；失败了怎么办；循环什么时候继续、什么时候停；一次运行留下什么证据。模型产出的是 token，把任务做完的是 harness。这中间的一切都归它管。

六月我写过，[Fable 5 把 AI 工作的单位从一次回答变成了一次运行](/blogs/fable-5-managing-ai-autonomy)，稀缺技能不再是写 prompt，而是设计让运行有边界、可检查、可逆的 operating contract。Harness 就是这份合同的产品化形态。Composio 那个分布，就是八个团队给同一个工人写了八份不同合同的样子。

我在自己桌面上每天看到它的缩小版。我几乎每天并行用 Claude Code 和 Codex，常常对着同一个仓库。我真正盯着的差别全是 harness 层的杠杆：动手前各自把哪些文件读进上下文、各自愿意让一次运行跑多久、一步失败之后各自怎么处理。这些是合同条款的差别，不是智力的差别。同一个工人，不同的管理者。

## 一家模型公司把 harness 白送了

DeepSeek 8 月 13 日的发布不是玩具级的。仓库落地就是 219 个包、64 天里 12,293 次提交——大约九周——带着 Web UI、headless 运行器和 Python SDK。它是开发者预览版，而且说得很响：README 里用全大写警告：兼容性说破就破。在 Hacker News 上，[一家常年被指控抄袭的公司得到了一句不寻常的评价](https://news.ycombinator.com/item?id=49285244)："这次它看起来相当原创。"

它开源那周我就把仓库 clone 了下来，做了一次完整拆解——十四个分析 agent 扫过源码树，锚定在 47f9438 这个 commit，做了几百次文件级核对。下面的论断是我在代码里验证过的，不是从报道里转述的。

在讲战略之前先做一个交代，因为我七月论证过这件事的另一个形态。[那篇文章](/blogs/why-ai-companies-are-becoming-deployment-companies)里，"deployment 能力比模型访问权更稀缺"的证据是各家厂商在人身上砸几十亿美金——把工程师派驻到客户现场。这次发布是同一个赌注换了形态：服务是 deployment 能力的人肉形态，harness 是它的软件形态。厂商现在两头都在下注。

## 三个可以去仓库里验证的动作

**格式投降。** DeepSeek 的 harness 逐字段采用了 Claude Code 的 SKILL.md 格式——而且仓库里的设计笔记显示，他们先造了自己的 skill 格式，然后亲手删掉，转投竞争对手的标准。它零配置读取你的 `~/.agents/skills` 目录，优先加载 `AGENTS.md` 指令文件、以 `CLAUDE.md` 作为回退。你的 skill 和指令文件第一天就能用、一字不改——这是最重要的两类资产。

**诚实的子集。** 它给 Claude Code hooks 做的桥接层不假装自己是克隆。它自己的 README 写明：Claude Code 的 30 种 hook 事件里有 23 种不支持，并逐一列出哪些字段只记录、不执行。把"部分兼容"明说出来是一种设计立场——大多数兼容层死于沉默的缺口。

**收编对手。** 最反常的一个：Claude Code 和 Codex 被挂成了它的 subagent provider。在这个 harness 里面，竞争对手的整个产品是一个可以把任务委托过去的节点。对手没有被屏蔽，对手成了管线。

这三个动作加在一起指向什么？以下是我的读法——也只能是读法，因为意图不写在仓库里。Anthropic 把 harness 闭源、和订阅绑在一起：harness 是模型的护城河。DeepSeek 反着来：把 harness 白送、让它读所有人的格式，于是 harness 变成 token 的获客漏斗——token 才是它真正卖的东西。底下还有更锋利的一层：当一家厂商采用竞争对手的文件格式，对手的用户手里的资产就突然变成可携带的了。锁定生效的前提是资产不能移动。可携带性是双向的刀，DeepSeek 刚刚出钱把它磨快了。

## 反方的理由，认真对待

一个聪明的怀疑者有三条像样的反对意见，三条我都认一半。

第一条：单一 benchmark 就是噪声。有道理——所以这篇文章从头到尾没用排名，只用了"分布宽"这一点——它扛得住 Composio 自己列出的全部局限。还有一条边界值得直接认下来：短的、一发即中的任务里，harness 没多少决定可做，分布应该收窄——Composio 跑的恰恰是长的、多工具的工作流，正是合同干活最多的地方。如果有人做出反向实验，证明在那种场景下 harness 也无关紧要，我会真的修正结论。我还没见到。

第二条：DeepSeek 这个东西现在很糙。也对。一位提前拿到仓库权限的开发者[说得很直白](https://x.com/jiayuan_jy/status/2087911060154314963)：体验落后于 Claude Code 和 Codex，接口还在变，插件质量参差不齐。如果你这周就要干活，Claude Code 仍然是更成熟的工具——这篇文章没有任何一句话说不是。但注意"糙"指向哪边：恰恰是本文的论点。一个如此未定型的层，一家大厂连续九周、以日均近两百次提交的力度把它商品化——它还在剧烈移动。还在动的地面，不适合下锚。

第三条：harness 战争可能很快收敛，就像当年的 JavaScript 框架大战。有可能。但"会收敛、赢家未知"恰恰意味着：现在对任何一家 harness 做深度定制，到头来就是一笔沉没成本。这正是这一切在实操上的落点。

## 租模型，防动荡，攥住你的 skill

下面这套资产检验，我现在就用在自己的技术栈上；读到同一条新闻的 builder，可以直接拿走。

**租模型（rent the model）。** 模型天生就是被设计成可替换的——harness 这一层存在的意义之一就是保证这件事，两家厂商的行为都在确认它。任何焊死在单一模型上的工作流，都在为别人的定价权交房租。

**防 harness 动荡（expect the harness to churn）。** 投入在"把 harness 用好"上，慎重投入在"深度定制某一家 harness"上——专有配置、厂商特有的扩展、活在某个工具插件体系里的工作流逻辑。这一层的战争这个月才正式开打，每个参战者"兼容性说破就破"的警告都在告诉你：你的定制是你手里最不耐久的东西。

**攥住你的 skill 和证据（own your skills and evidence）。** Skill、指令文件、你的评估和反馈记录，现在是每个 harness 都会读的那一层。DeepSeek 删掉自有格式改投 SKILL.md，把这件事坐实了：这些文件正在变成跨厂商标准，也就是说无论谁赢，它们是唯一为你复利的一层。我把自己的 skill 和 AGENTS.md 式指令保持在可携带的形态，也保留"什么有效、什么被我否决"的记录——这个回路能复利，是因为写回什么由我决定。我刻意不做的，是把楼盖在任何一家 harness 的私有地基上。

一天就能做完的版本：列两栏。可携带的——skill、指令文件、评估集、反馈记录。被锁定的——只在某一家工具里才有意义的一切。这张清单就是你在这场战争里的仓位，而大多数 builder 从来没把它写下来过。

厂商们接下来一年要打的仗，就在这一层：把模型能力变成干完的活。你不需要押中赢家。你需要知道哪一层是你的。
