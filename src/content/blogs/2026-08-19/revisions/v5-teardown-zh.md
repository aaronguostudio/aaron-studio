# 我把 DeepSeek Harness 拆开了

新闻你大概已经看过了。8 月 13 日，DeepSeek 把自己的 agent harness 开源，MIT 协议，和 V4-Pro 转正是同一天，几个小时内 GitHub 星标就冲到几万。再往前两天，[Composio 发布了一个实验](https://composio.dev/content/best-agent-harness-deepseek-v4-flash)：同一个模型放进八个不同的 harness 跑三十个真实工作流，成功率从 46.7% 摆到 66.7%，每完成一个任务的成本差七倍。harness 很重要，模型公司亲自下场做 harness，大新闻——这些大家都写过了。

我找不到的，是对真正用 agent 干活的人最要紧的那个问题的回答：这东西里面到底是什么？所以我花了一周钻进仓库：十四个分析 agent 扫过源码树，锚定在 47f9438 这个 commit，逐文件核对了几百条论断。六月我写过，[AI 工作的单位已经从一次回答变成一次运行](/blogs/fable-5-managing-ai-autonomy)，稀缺技能是给运行设计操作合同——这个仓库是第一次有机会把一家厂商的完整合同从头读到尾。

里面有四样东西，真的改变了我对 agent 系统的理解。四样都不在发布报道里。

## 模型只被允许看到日志里的东西

DeepSeek Harness 的每个会话是一条只增不改的事件日志。仓库定义了 44 种事件——轮次边界、工具调用、审批、配置变更——其中只有 3 种是模型看得见的：你说的话、它说的话、工具返回的结果。剩下 41 种全是记给人和审计看的账。

让我停下来的是这个细节：模型看到的那份对话，根本没有被存储在任何地方。它在每次请求之前，从日志现算出来。而"模型看到的一切必须能从日志重建"这条规矩，不是写在文档里的承诺，是一个运行时检查——有个看门插件在每次调用模型前，把"从日志应该算出的内容"和"实际要发出去的内容"逐字节对比，对不上，这次请求就拒发。

想想这换来了什么。每个用 agent 干活的人都撞到过那个没法调试的时刻：agent 做了件莫名其妙的事，而你不知道它当时到底看到了什么上下文。在这套设计里，这个问题永远有精确答案。会话的分叉、恢复、回放不再是三个功能，而是同一份日志的三种读法。成本核算是白送的，因为 token 用量就盖在同一批事件上。连他们的测试系统都骑在这上面：录一次真实会话，日志本身就是一份确定性的回放脚本——CI 里不需要 API key，真实的工具和子进程照常跑。

这套设计的账单也是实打实的，而且 DeepSeek 是明知故付。常驻的代码执行内核——模型写的程序在多次调用之间保留变量——会更快也更省，但仓库里的设计笔记显示他们否决了它，理由是跨调用的状态没法从日志重建。Anthropic 在自家的代码执行接口里恰恰加上了这个功能。两家公司看着同一笔交易，朝相反方向走：一边押性能，一边押可重建。另外，日志只会越来越长——压缩只是把旧内容从模型视野里遮掉，一个字节都不删，省的是 token，不是硬盘。

如果只能从这个仓库带走一样设计，我明天就抄这个，哪怕是微缩版：每次请求前，断言你要发出去的上下文和你自己的记录一致。五行代码，静默的上下文漂移就从生产环境的悬案，变成开发阶段的一声巨响。

## Agent 主循环就是一行配置

"一切皆插件"听起来像每个框架的营销话术。在这里它是字面意思，而且彻底到我没见过第二家。驱动 agent 的那个主循环——决定什么时候调模型、跑工具、继续还是停下的东西——是 YAML 文件里的一行。加上 `disabled: true`，agent 就不存在了。产品的默认配置也不是特权代码：它只是打在一棵空树上的第一层补丁，你自己的配置补丁用的是同一种语法、站在同一个层级。

两个细节能看出这件事做得有多彻底。运行 `dsh --dump-config`，它打印出你这台机器实际启动的那棵树——打印出的每一行，都是你可以用自己的补丁合法替换的目标。界面上的四种"模式"（标准、代码、极简、创造）就是四份 YAML 文件；代码模式——模型写程序来编排工具、而不是一个一个调——和标准模式的差别，只有一行。

这种灵活性的代价，写在仓库自己的事故报告里。组合发生在运行时，编译器就救不了你了。DeepSeek 公开的四篇事故复盘里，两篇是纯粹的组合期失误：一个配置表达式写错了字段位置，所有模式下的文件工具集体静默失效；一个多余的 `export default`，让加载器悄悄丢掉了插件的依赖声明——178 个绿色单元测试加 100% 行覆盖率，陪着一个真实编辑器一连上就崩的产品一起上了线。两次的修法都一样：再加一道机器检查。这个仓库现在跑着 27 道这样的检查，站在编译器本来站的位置上。

我的判断：对一个把未来押在生态上的平台，这笔交易是自洽的。对我们大多数人，值得偷的不是插件树，而是 `--dump-config` 这种透明度：一条命令，打出你的系统实际在跑什么，每一行都可以被覆盖。

## 缓存纪律，用 CI 强制执行

按发布那周的定价，DeepSeek 的缓存命中价格大约是未命中的五十分之一（V4-Flash）到一百二十分之一（V4-Pro）——8 月 17 日起改成了分时定价，但比例本身说明问题。对一家卖 token 的公司，你的请求有没有复用稳定的前缀，不是性能细节，是毛利。

仓库就是按毛利来对待它的，而且是机械化地对待。工具的 schema 按一个与语言环境无关的固定顺序排序，保证提示词前缀在任何机器、任何重启后逐字节稳定。易变的事实——时间、环境状态——完全不进系统提示词，只在发生变化时作为落日志的消息注入，免得击碎缓存前缀。每个包的 README 被强制要求写一节"KV Cache effect"，声明自己对前缀的影响，缺了这节 CI 直接红。还有一条真实 API 的端到端测试，断言会话里除第一次之外的每个请求，缓存命中的 token 数必须大于零。任何打破前缀稳定性的回归——一个时间戳混进系统提示词、工具列表自己变了顺序——在烧到任何人的钱之前，CI 先红。

大多数 agent 框架把缓存命中当天气，这一家把它当带测试的不变量。这也是"谁造的、为什么造"最清晰的指纹：只有模型公司会围绕自家价目表来设计 harness。而这三样技术——固定排序、易变内容出前缀、缓存命中断言——任何技术栈这周就能抄走，不管你跑的是谁家的模型，都能省钱。

## 仓库本身可能是最值钱的展品

DeepSeek 的 harness 用 64 天、12,293 次提交建成——而仓库里 markdown 文件比 TypeScript 文件还多。这不是懒散，这是第一次有人把"agent 写了绝大部分代码的工业级工程"的现场公开出来，而他们围绕这件事建的那套流程，在我看来是整个仓库里最好的东西。

开工第二天写下的一篇流程笔记，把操作理论说破了：相比写在文档里的约定，agent 遵守被强制执行的检查要可靠得多；而当劳动由 agent 完成时，"工作量太大"就不再构成反对理由。于是规则密度一路拉高——每个非平凡改动必须附带一篇设计笔记（现在有 683 篇），凡是机器能检查的都上机器检查——唯一留给人类判断的，是"这个改动算不算平凡"。

两个机制特别扎眼。有一个 `rejected/` 目录，存放他们否决过的方案，每篇冻结着当时的理由——还有一条常规：将来谁想重提，必须击败记录在案的论证，而不是从头再吵一遍。看过 AI（或者新同事）信心十足地重提上个月刚被否掉的想法的人，都能认出这是什么：一套免疫系统。另外，这里的事故复盘不允许以"教训"收尾——必须以机器检查收尾，而且要验证过"把原 bug 恢复回去，检查确实会变红"。上面那次覆盖率作秀事故的产出正是如此：一条不需要 key、走真实加载路径的测试，被证明过 bug 一回来它就红。

就算这个 harness 输掉战争，这层流程也是值得搬走的战利品。每个 AI-native 团队都在暗暗琢磨的问题——当劳动的边际成本塌下来，工程纪律应该长什么样——这是目前最具体的公开答案。

## 战略也写在代码里

三个动作，都能去仓库里验证。第一，它直接采用了对手的标准：逐字段兼容 SKILL.md（设计笔记显示他们先做过自己的格式，后来删了），零配置读取 `~/.agents/skills`，优先加载 `AGENTS.md`、兼容 `CLAUDE.md`——你的 skill 和指令文件第一天就能用。第二，不支持的功能它明说：Claude Code hooks 的兼容层在 README 里写明 30 种事件有 23 种不支持，不装克隆。第三，它把竞争对手变成了自己的插件：Claude Code 和 Codex 被接成 subagent，任务可以直接委托给对手的产品去跑。

我的读法——也只能是读法，因为意图不写在仓库里：Anthropic 把 harness 闭源、和订阅绑定，是给模型修护城河；DeepSeek 把 harness 白送、让它读所有人的格式，是给自己真正卖的东西修漏斗：token。七月我论证过[稀缺的是 deployment 能力，不是模型访问权](/blogs/why-ai-companies-are-becoming-deployment-companies)——当时的证据是各家在部署工程师身上砸几十亿美金，这次是同一个赌注的软件形态。而且这上面还带着刃：当一家厂商采用竞争对手的文件格式，对手用户手里的资产就突然变成可携带的了。可携带性是双向的刀，DeepSeek 刚刚出钱把它磨快了。

当前状态的老实话，出自仓库自己之口：防死循环的守护只能劝告、超过最高阈值后彻底沉默；bash 命令没有超时预算；hooks 兼容层对拦截指令 `continue: false` 只记录、不执行。一位提前拿到仓库权限的开发者[说得很直白](https://x.com/jiayuan_jy/status/2087911060154314963)：日常体验还落后于 Claude Code 和 Codex。"现在还糙"是公允的总结——这周就要干活的话，它还不是那个工具。

## 我从里面带走什么

三样东西直接进我自己的技术栈。日志设计里的那条请求前断言——五行代码，让上下文漂移变成一声巨响。缓存纪律——工具固定排序、易变事实出前缀、一条断言缓存命中的测试。还有在我自己的仓库里建一个 `rejected/` 目录，因为我的 agent 也会重提死掉的想法。

再加一个看大局的框架。模型这一层，你是租的——它天生被设计成可替换，两家厂商的行为都在确认这一点。harness 这一层会动荡——这个仓库自己的全大写警告就是证词，今天对任何一家 harness 做深度定制，到头来很可能是一笔沉没成本。真正为你复利的，是每个 harness 现在都会读的那一层：你的 skill、你的指令文件、你对"什么有效、什么被否决"的记录。DeepSeek 删掉自有格式改用对手的，把这件事彻底坐实了。这周花一个小时，把你的 AI 资产分成可携带和被锁定两栏——在这个仓库里泡了一周之后，这是它留给我的最清楚的一条指令。
