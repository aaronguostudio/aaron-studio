昨天，我的 agent 产出的一份工作，附了一张我没法把账目对回到工作本身的发票。今天，同类型的工作——包括这句话本身——跑在我自己的芯片上，harness 里根本没有计费面。中间的模型是一个 27B 的开放权重文件，从 Hugging Face 拉的。版本要钉死，因为收据才算数：DeepSeek Harness 0.1.0-rc.8，Qwen3.8-27B（Unsloth Q8_0），Ollama 跑在 M5 Max MacBook 上，128GB 统一内存。

没有云 token。没有 meter。

这篇文章的重点不是 27B 模型有多能打。评测文章比我写得好，而且那些评测自己也在强调：接近前沿不等于追平前沿。重点是 per-token 的 meter 离开房间的那一刻，我的工作流里发生了什么变化：当智能不再是租来的时候，你买到的是什么；当 meter 消失后，质量责任去了哪里。

## 交叉点刚刚变成真的

能力这一侧的交叉发生在 2026 年 8 月中旬，阿里开源了 Qwen3.8-27B。按[品玩](https://www.pingwest.com/a/316634)和 [Pandaily](https://pandaily.com/qwen3-8-27b-new-model-kill-line-local-opus-consumer-hardware-aug2026) 的报道：大约两天内下载量破百万，登上 Hugging Face 全球趋势榜第一，四天之内成为 Cline 开发者选择最多的本地模型。它在 Artificial Analysis Intelligence Index 上拿到 52 分，进入和 GPT-5.6 Luna、DeepSeek V4 Flash 同一档。社区给它起了个外号：本地 Opus 4.6。起这个外号的报道，同时也是加上免责声明的报道：最难的任务上，差距是真的。

这个免责声明恰恰是重点。一个模型不需要把前沿打遍，才能改变你买什么。它只需要让某一类工作达到它的线，并且小到你可能已经拥有的机器能跑——4-bit 量化大约 17GB 权重，我本地跑的 Q8 量化大约 28GB，所以这台机器有 128GB。

价格同一时刻在动。8 月中，DeepSeek 把 V4-Pro 高峰时段的输出价从每百万 token 6 元调到 27 元——4.5 倍——并引入峰谷计费；同样按报道，智谱和 Kimi 此前已经调过价，而一个 coding agent 单任务吃掉几十万 token，现在已经是常态。

每一次重复运行都要再付一次 meter，而 meter 跟着报价单走，报价单现在跟着季节走。我不赌报价单。我的线画在能力这一侧，因为报价单是那个我控制不了的变量——而它刚刚在我最关心的那个数字上，动了 4.5 倍。

## 边际成本归零暴露了什么

当一个工作流里的 meter 消失，有一项从来不在发票上的成本浮出水面。它一直都在，只是订阅替我付了。

本地模型的余量更小。发布之初，按报道，它比同档模型想得更久，而且硬任务上还是会错——Simon Willison 给它 21 分钟的推理，换来一只骑自行车的鹈鹕。这次会话里，是流程接住了模型接不住的东西：风格扫描器否掉了初稿的结尾——它是一句总结，不是一条规则；claim ledger 拒绝了一个我原本想钉死的 Qwen 发布日期，因为各家报道的日期不一致，所以文章现在写的是 8 月中旬。这和 [我 8 月写过的那篇](/blogs/ai-made-process-cheaper-judgment-is-still-expensive)是一面镜子：流程变便宜了，判断力仍然贵，178 个绿的测试曾经放过一个真实的 loader 故障。

在云端的旗舰模型上，模型自身的余量有时候能把工作扛过去。在本地 27B 上扛不过去。于是产出和 slop 的差别，来自模型外面的机器——会拒绝的 gate、带上下文的 skill、留得住的 memory、记下来的 log。[我在 DeepSeek Harness 拆解里论证过](/blogs/deepseek-harness-teardown)：completion、cost、audit 实际是在 harness 这一层决定的。本地栈只是拿掉了一个我过去当成三者代理的界面：计费页。

审计本身也变了性质。在云端，供应商的事件日志是内部记录，顺便产生一张发票。在本地，同一条 append-only 日志是唯一存在的收据——我现在就可以打开它，读这个会话写下的几千行：模型声称了什么，gate 拒绝了什么，我逐行改了什么。这种可见性是任何云供应商不会给你的，因为可见性本身就是产品，发票只是它的证据。

## 自指，我把话放这

这篇文章是由它描述的系统写出来的。我是在自己的频道上评自己的电台，任何人都有权把这叫利益冲突。我不打算反驳。收据是我处理它的方式：上面每一条承重事实都钉了版本，每一个对抗性检查都留在工作会话里，不在一个被剪辑过的故事里。扫描器标掉了初稿的措辞，ledger 排除了一个我原本想要的精确日期，会话日志记录了整场生产——模型的声称、gate 的拒绝、我的修改。这比我任何关于这台机器诚实度的口头声明都硬。

不是让你信任模型写了这篇文章。是让你看见环绕它的机器做了什么。

## 本地栈放弃了什么

一台 128GB 的机器有购置价，假装它没有，比这篇文章试图纠正的错误更糟。而且前沿仍然持有硬任务区：深度推理、跨多文件的长程重构、需要能力曲线顶端的单次任务。这些留在云端。交叉点是 per work class 的，任何"一切皆可本地"的版本，撞上周硬任务区那一周就会错。

站得住的框架是成本结构。发票是经常性的：每次运行都回来，永远回来，跟着报价单走。机器是摊销的：只付一次。当 per-task 计量不再是零头、而是结构性成本——agent 工作正在这个位置，因为 agent 重复运行——两条曲线相交。我不是说这个交叉点能证明任何一次特定购买。我说的是算术变了，而且变化是按工作类别发生的，不是按模型。

一个我真正会拿它来行动的操作含义：在跨越交叉点的类别里，投资顺序翻转——harness 变成产品。本地货架上的模型是可替换的：下一代 27B 级发布落地，换掉文件就行，gate、skill、memory、audit 原样继续工作。会复利的资产不是模型文件，是读取它的那一层可携带的机器。

## 本地交叉点测试

所以给你测试，不给结论。测试可以在你自己的工作负载上跑，我的结论不能。

任何一个可重复的 agent 工作类别，问三个问题：

1. **Capability**：27B 级模型在**你自己的检查标准**下（不是 benchmark 的），能不能稳住这一类？
2. **Recurrence**：per-token 计量对这一类是结构性成本，还是零头？
3. **Audit**：你的 harness 的 gate 加 log，能不能替代供应商 SLA 和发票过去给你的可审计性？

三个全过，这一类迁本地；挂一个，这一类继续租，并且是清醒地租。验证只要一小时：挑一个真实工作负载，走你自己的工作流，用 27B GGUF 跑一遍，读审计日志，diff 对比上一次云端的同类运行。你找到的差距，就是你的线。

所以从现在起的规则：别再问供应商计量花了我多少钱。问它对我的价值是多少，按工作类别问，只迁跨过线的那些——因为当边际成本归零，模型就不再是你租的东西，环境才是你买的东西。
