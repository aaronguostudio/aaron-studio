# 论证备忘录

## 核心论点

Per-token 云端是在租智能；27B 级本地模型 + 开源 harness 是在买环境。当本地模型跨过"日均可执行工作"的能力线后，决定生产质量的就换成了模型外面的机器——gate、skill 目录、memory、审计——而不是接了哪个模型。

## 为什么现在值得写

- 27B 尺寸第一次压进"旗舰同档能力区间"（AA Index 52），两周破百万下载，Cline 开发者 4 天内默认本地选它——交叉点从观点变成行为数据（2026-08，品玩/Pandaily）。
- 同时刻云端在涨：DeepSeek V4-Pro 峰时输出 6 -> 27 元/MTok + 峰谷计费（2026-08）。"线画在报价单上就会跟着报价单移动"，本地是第二条定价曲线。
- DSH 0.1.0-rc.8（2026-08-19，12,940 commits）证明 harness 层还在高速变动——现在是写"harness 即环境"最及时的时点。
- 系列收尾条件满足：DSH 系列前四篇回答"harness 决定什么"，本篇用本地栈的生产收据回答"模型不再是租的以后，投资去哪"。

## 机制解释

1. 云端的成本结构：每个 agent 任务 = 几十万 token 的经常性支出 + 不可审计的账单面 + 峰值涨价风险。执行越自动化，账单越大——这是结构性的，不是用量问题。
2. 本地越线事件：27B（4bit ~17GB）把"够聪明确定性的日均可执行工作"压进个人硬件尺寸。MoE 的总权重驻留问题被 dense 级小模型直接绕过（在 27B 这个尺度上）。
3. 结构变化：当 agent 工作边际成本 ~= 0 后，原来被账单掩盖的成本全部浮出水面并重新定价——质量成本。谁来负责质量？答案：模型 margin 越小，gate 密度越关键（08-26 文的 loader 案例的镜像：云端有 ceiling 兜底，本地天花板低，拦截必须在系统层完成）。
4. 所以 harness 从"工程细节"变成"质量来源"——这正是 DSH 系列论证过的层，现在它接管了计费面退役后的全部职能。

## 证据地图

- 本机收据（一手）：rc.8 + Q8_0 + M5 Max 128GB + Ollama 无计费面（C1/C7/C8）；本会话事件日志 9,000+ 行；gate 在真实生产中拦截（风格扫描器 / claim 排除 / 事实核验改日期）。
- 市场时点（二手，带源）：Qwen3.8-27B 发布与下载（C3）、Cline 行为数据（C3）、DeepSeek 提价（C4）、单任务 token 量级（C6）、4bit 尺寸（C12）。
- 系列内（前文）：teardown 的"harness 决定 completion/cost/audit"（2026-08-19）、"机器能查的交机器"（08-26）、envelope 成本（09-02）。
- 反方证据：高难差距 + "想太多"（C5，品玩自认 + Willison 实测 21min）；硬件购置价（C1 的 128GB 不是白来的）。

## 需要承认的反方观点

1. 自指：我评的是自家电台。承认 + 处理：冲突上正文；收据版本锁定；gate 是敌对设计（会骂我、会排除我、会改我）。
2. 工作类别挑选：我只挑了够得着的类别。承认：交叉点是 per work class 的；正文给三问表 + 不迁移清单（高难推理 band、长时程代码库级重构、需要最高 ceiling 的一次性任务）。
3. 摊销 vs 经常性不是"免费"：128GB 花了真钱。承认：这正是论点本身，成本结构对比。

## 对反方的回应

- 1 的回应核心：自指是这篇唯一诚实的写法——生产机器 = 文章对象，利益冲突被做进证据链而不是公关话术。
- 2 的回应核心：我不 claim"一切皆可本地"，我 claim"存在一条可测量的线，线的存在本身改变了投资决策"，并给读者自己测的工具。
- 3 的回应核心：经常性支出永远回来，摊销只回来一次；当工作量跨越某点两条曲线相交——交叉点就是操作点。

## 可复用框架

**本地交叉点测试（Local Crossover Test）**——对任一可重复的 agent 工作类别，问三个问题：
1. Capability：27B 级模型在你的检查标准下（不是 benchmark）稳不稳？
2. Recurrence：这个类别跑得够频繁，per-token 是结构性成本还是零头？
3. Audit：你的 harness 的 gate+log 能否替代 vendor SLA/发票给你的可审计性？
三个全过 -> 迁本地；挂一个 -> 这个类别继续租。
一小时验证版：挑一个真实工作类别，用 27B GGUF 走你自己的 harness 跑一遍，读审计日志，diff 对比上次云端同类任务。

## 对读者的启发

- 你的 token 账单里隐含一个假设："智能必须按次购买"。27B 越线后这个假设对一半工作类别失效。
- 投资顺序变了：先投资 harness（gate 密度、memory、审计），模型在本地是货架商品，随换代即换。
- 一句话决策规则：invoice 是经常性成本，purchase 是摊销成本；agent 工作的边际成本归零后，质量责任的唯一住处是系统层。
