# Canon Note

## Canonical Idea

When a local model clears the daily-task capability bar (Qwen3.8-27B class, mid-August 2026), the unit of purchase shifts from intelligence to environment: the per-token invoice is a recurring cost that follows a moving price sheet, the local machine is an amortized purchase, and quality responsibility moves from the vendor's ceiling to the harness's gates, skills, memory, and audit log.

## Reusable Frame

**Local Crossover Test** (per workload class, not per model):
1. Capability — 27B-class model clears this class's bar on the reader's own checks, not a benchmark's.
2. Recurrence — per-token metering is structural cost for this class, not rounding error.
3. Audit — the harness's gate + log replaces what the vendor's SLA/invoice gave.
Pass all three -> move local; fail one -> rent that class deliberately. One-hour validation protocol: run one real workload on a 27B GGUF through your harness, read the audit log, diff against your last cloud run of the same class.

Companion investment rule: in classes that cross, investment order flips — the harness becomes the product; the local model file is a swappable shelf item.

## Claims Added

- The crossover is a cost-structure decision (recurring vs amortized), not a capability ranking.
- Zero marginal cost resurfaces the quality cost the invoice previously covered; the audit log replaces the invoice as the receipt.
