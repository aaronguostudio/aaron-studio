# Canon Alignment

## 文章当前判断

这篇 Learn 文章不是要建立一套新的行业分类，而是解决 Aaron 反复遇到的实际问题：AI 能快速生成文档，但团队仍然需要把模糊审美反馈变成可检查、可复用、可导出的设计决策。

## 与旧文章的呼应

- 延续 “生成不是生产” 的判断：主题名或一次生成不能代替完整系统。
- 延续 owner / boundary / evidence：历史来源、本站解释、Token、组件规则与对比度结果都要留下可审查证据。
- 延续 intent → run → review → memory：模拟器把选择编译成 brief 与 Token 清单，让下一次运行可以复用。

## 观点升级

旧版把 `Document Visual Language`、五层栈、四条轴和若干 archetype 放得过于接近行业术语。本次升级把它们明确标成本站工作模型，并把主要词汇收敛到 theme、design token、component、pattern、design practice、historical tradition 与 WCAG criteria。

## 需要避免的惯性

- 不用一句漂亮总结冒充正式定义。
- 不把 `Organic Humanist`、`Institutional Modern` 等本站命名包装成通用分类。
- 不把 DTCG Community Group Final Report 写成 W3C Standard。
- 不让概念解释压过读者真正要完成的文档任务。

## 可以加入的 Aaron 判断

保留最有 Aaron 特征的判断：当执行变便宜，瓶颈会上移到判断、边界与评审。这里的具体表达是：主题可以帮助选择，但只有 Token、组件、模式、来源标签与验收准则才能让结果被复现和审查。

## 站内链接建议

后续若 Learn 支持正文内链，可以连接到设计 Token、组件模式、无障碍 PDF，以及 “AI became my operating system” 中关于工作流与证据的文章；当前不添加不存在的 Learn slug。

## Alignment Decision

保留 `Document Visual Language` 作为已声明边界的文章标题；删除主要交互中的自造 archetype，把五步顺序和四条轴明确标为教学模型，并用一手来源支撑已有术语。
