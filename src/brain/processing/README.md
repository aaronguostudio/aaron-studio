## 两周试点：2026-09-05 至 2026-09-19

先确认一页当前基线，再逐来源处理另外两至四场相关会议。每场重要会议用一分钟补充，按需生成变化卡；每周约十分钟复核。没有足够证据时保留未知，不要求凑够会议数或洞察数。

观察三项：把提议错当需求的次数；需要 Aaron 重复解释背景的次数；每次复核耗时。当前尚无使用数据。至少在一次真实项目任务中使用上下文后，再评估是否值得开启定时采集。

## 其他项目如何使用

初期在本地会话直接调用 Aaron Studio 的 `tiles/brain-context/SKILL.md`，提供项目名称、任务和受众。skill 按需读取项目节点及引用来源，返回简短上下文。不要把整个 Brain 复制进项目。

需要长期接入某个仓库时，再在该项目 AGENTS.md 放置本地入口约定：任务涉及历史范围/需求/决策时调用 brain-context；未确认内容只能用作问题；执行状态要查当前代码和任务系统。项目指针应通过本地配置解析，私密内容不进入共享仓库。本次未修改其他项目。

## 维护规则

证据保留在 world/_archive；变化卡保留判断过程；项目节点维护当前状态。详细格式与权限以 [skill](../../../tiles/brain-context/SKILL.md) 为准。采集草稿不会自动批准业务事实，修改当前范围需要对应的明确决定。旧日期证据不因重新读取而变新。
