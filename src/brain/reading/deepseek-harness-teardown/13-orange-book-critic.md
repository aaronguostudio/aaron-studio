# orange-book-critic

花叔的橙皮书是发布 24 小时内完成的用户视角实测记录，其最大价值不是观点而是一手数据：所有关键数字都附带可复现的取数命令，且我在仓库（HEAD 47f943859b，恰为书的快照版本）逐项复核后全部吻合——包括 12,293 次提交、683 篇设计笔记、11 篇被否提案、4 篇 postmortem、27 道机械门禁、219 包 invariant.ts、reflect.ts:290 的逐字抛错、以及书指出的三处至今未修的文档-代码不一致（vendored 包 private:true 声明为假、创造模式 SKILL.md 仍引用已改名的 cordis_inspect/mount/unmount、自指工具 5 vs 7）。书的方法论亮点是「差值称重法」拆首轮账单、同模型同任务的 PTC 严格对照、以及对自身验证边界的逐条诚实标注（哪些实跑、哪些只读了文档）。局限是结构性的：用户视角能看见账单、日志、界面和撤回决策，看不见源码机制（agent-loop、effect/disposer、waterfall 语义）、测试基建（keyless snapshot、per-file 100% 覆盖门禁、record/replay）、类型系统（Branded id、typert 生成链）与过程制度的执行细节，这些是工程分析必须补上的另一半。作为增量输入，这本书最适合承担的角色是：提供工程文档不会记录的运行时实测数字（缓存 64 倍数、中文 token 密度 1.71、开机费构成），以及四篇 postmortem 和十一篇被否提案之外的第三种证据——产品在真实用户手里第一天的摩擦面。

## 首轮入场费解剖：用户问 29 token，harness 先付 13,809 token

机制：作者把首轮请求逐块发给 API 用 max_tokens=1 称重做差：25 件工具说明书 6,510 token（47.0%）、本机 57 个 skill 的目录清单 6,242（45.1%）、系统提示词 844（6.1%）、运行环境快照 129、协议固定开销 82、用户真正的问题只有 29 token（0.2%）。其中最贵单件是 workflow 工具说明书 979 token（本次任务零调用）；45% 的入场费来自用户自己的 skill 资产被自动扫入（~/.agents/skills），使开机成本从约 7,600 涨到 13,838（+82%）。

证据：书 §06「你打第一个字之前，账单已经13,809」；称重方法（zstd 解日志取 request/header + curl max_tokens=1 差值法）全部给出可复现命令

价值：这是公开材料里罕见的、对 agent 固定开销的逐项实测解剖。它把「工具定义和 skill 目录才是成本主体、用户输入可忽略」这个结论钉死在数字上，直接指导任何 agent 系统的 context 预算设计——skill 简介长度是每会话公摊成本

## PTC(Code mode) 严格对照实验：同模型同任务，小任务上全面更贵

机制：同一任务（3 个小文件统计行数/字符数写报告）、同 V4-Pro、同推理档，只换模式跑两遍：标准模式 21.9 秒 / 7 次工具调用 / 输出 1,416 token；PTC 305.9 秒 / 模型开口 5 次但程序内派发 15 次 / 输出 17,235 token（76% 是 thinking）。首轮输入 PTC 反多 9%（15,040 vs 13,842）：工具参数表从 26,894 字符缩到 897，但 25 件工具的类型定义整体搬进系统提示词（4,101→35,643 字符）。PTC 省的是中间结果体积（10 次内部操作的输出从不进模型上下文），不省工具说明书。

证据：书 §08「我跑了两遍，账跟直觉反着来」两张对照表；§06 有一张宽松对照先行版并自我标注口径缺陷

价值：对「让模型写程序编排工具能省 token」这一流行叙事的最干净证伪之一：报关单只是换了位置，赌的是中间产物体积。给出了清晰的适用判据——步骤多、中间产物大、只要结论的任务才值得切 PTC。作者同时诚实标注这是单次实验不能外推

## 自造工具 19 步实测：前 14 步在读自己的说明书

机制：创造模式下让 agent 现场造 count_chinese 工具：全程 19 步 24 次工具调用，前 14 步 20 次全部是自省（6 次 cordis_inspect 系工具、6 次翻安装目录、4 次读 .d.ts 类型声明、3 次搜 defineTool、1 次自主加载 cordis-plugin-development skill），真正动手只用最后 4 次。会话日志的 request/header 只在工具清单变化时记录，全场两条：initial 32 / change 33。写出的正则含 CJK 三段区间（扩展区+常用区+兼容区），超出测试用例需要。

证据：书 §07 全章；我在仓库验证了 7 个注册工具名（cordis_define/inspect_list/inspect_query/inspect_self/run/stop/undefine，grep packages --include='*.ts'）与书报的「文档说 5 个实际 7 个」一致

价值：「先查规格书再写」vs「凭记忆写」的行为差异被日志完整捕获，且 request/header 的按变化记录机制免费提供了工具清单演化的审计轨迹。同时边界清晰：动态插件不落盘、不过重启、不能自动转正——能力与持久化被刻意切开

## 44 行日志 / 44 种事件 / 3 种模型可见：Model-visible ⟺ logged 的实测面

机制：一句「说明当前目录有哪些文件」留下 44 行物理记录（事件编号到 125，打包行每行装多条碎片），逐行标注后模型可见的只有 6 行（3 条 user/message、2 条 assistant/message、1 条 tool/result）。全产品 44 种事件类型中仅 3 种模型可见，其余 41 种（权限三件套、审批、轮次边界、碎片、标题调用）只进日志。每次发请求前代码把「真要发的消息列表」与「从日志投影应得的列表」六项逐项比对，不一致抛异常拒发。

证据：书 §05；我验证 docs/persistence-catalog.md 四级标题恰 44 个、根 AGENTS.md 有 Model-visible ⟺ logged 规则原文

价值：把「模型到底看到了什么」从玄学变成可逐字节复原的事实，且投影机制让分叉/恢复/回放变成同一份日志的三种读法。副产品是缓存天然命中（append-only 投影 = 上次请求的延长）。代价书也算了：一个 echo 任务 35 条记录、无保留期策略、无法精确删除单句

## 四篇 postmortem 的题眼：178 个绿测试 + 100% 覆盖率照样在生产完全不工作

机制：0001：export default apply 让加载器丢弃并排导出的 inject 声明，178 个测试全部手工挂载不经过真实加载器，唯一的端到端测试因 CI 无 key 跳过、本地靠三天前的旧编译产物「通过」；调试时优雅理论推了数小时，一句 printf 几分钟定位（且优雅理论后来被证明是第二个 bug）。0002：配置表达式写错位置致三个文件工具永久禁用，快照测试被刷新后忠实验证「稳定地失败」。0003：agent 起替身服务器拿 200 就宣布验收成功。0004：沙箱善意提醒与致命诊断共享前缀，空搜索结果被误判为沙箱故障，并自曝 stderr 带内归因原理上可被子进程伪造。

证据：书 §12；我验证 docs/postmortem/ 恰 4 篇（0001-0004，各配 en/zh/i18n 三文件），0001 正文含 "178 green unit tests and 100% line coverage" 逐字

价值：对 AI 写码团队最实用的四条反模式：覆盖率不证明按交付方式工作、快照刷新是 fixture 生产不是正确性审查、替身服务证明不了目标页面、带内文本信号可伪造。「信 trace 不信理论」对人机协作同样成立

## 「工作量大不构成成本论据」——AI 开发下规则密度的经济学翻转

机制：开工第二天的制度笔记原话：agents 遵守机器强制的门禁远比遵守文档约定可靠，且当劳动由 agent 完成时 'a lot of work' 不再是反对理由。落地为 27 道机械门禁 + 12 个生成器、219 包每包强制 invariant.ts（184 个空实现必须以 'No runtime invariant:' 开头写包特有理由）、每包 README 强制 KV Cache effect 与已知限制段、Agent Note 与代码同 PR、归档笔记哈希冻结（426 条封存记录）。唯一不自动化的一条恰是「改动平不平凡」的判断，明确留给人。

证据：书 §13；我验证 find packages -name invariant.ts = 219、grep 'No runtime invariant:' = 184、verify-* 27 道（35 文件减 8 个 spec）、md 2,355 > ts 2,319、12,293 commits / 首提交 2026-06-10

价值：这是全书最可迁移的一个洞察：传统上被「谁来写」否决的重制度（每包文档、每改动笔记、双语归档），在 agent 干活的前提下边际成本趋零，于是最优规则密度大幅上移；而分界线——能机械化的全部机械化、判断力留给人——是可以直接照抄的

## 冲突裁决 = 当场抛错点名先占者；失败模式 = 安静而非塌

机制：两个插件抢同一 service 位置时，vendor/cordis/src/reflect.ts:290 一行 throw 点名先注册者，不静默覆盖不按加载顺序。但 cordis 把「依赖的服务无人提供」定义为合法的 PENDING 状态（永远等待、不打印），这是热插拔的前提；产品层在启动时刻加两道审计把「等待」强行翻译成「失败」。扩展方式是替换配置行而非叠加插件；改一行不许只改一个字段，补丁整段替换以保证单点可读。

证据：书 §11；我验证 reflect.ts:290 逐字命中 throw new Error(`service "${name}" has been registered at <...>`)，preset 四份清单 251/262/262/62 行与书一致

价值：「框架层的特性在产品层必须是错误」这个转译动作，是插件架构产品化最容易漏掉的一步。书对失败形态的判断——拔错零件最可能的后果不是塌是安静——比大多数工程文档更准确地描述了 DI/懒加载系统的真实故障形状

## 撞墙给梯子，不在门口劝退：被线上数据打碎的直觉

机制：最早把「你跑在只读沙箱下」写进系统提示词，结果首次人工会话 12 轮里 5 轮零工具调用直接放弃（软性封锁）。改为：系统提示词四千字符零沙箱字样，策略作为独立运行时快照注入，且只读档措辞明写「别光凭此策略拒绝，去试工具并跟随其返回的拒绝与升权指引」；被拒时模型收到两行标记+梯子（sandbox_permissions + justification，同轮限一次重试，只能升不能平移，只读是地板），四种拒绝结局措辞逐字不同以指导模型改方案还是放弃。

证据：书 §02「他们上线过一句话，又被自己的实测数据打回来」及撞墙链路实录

价值：对任何给 agent 立规矩的场景可迁移：限制的存在感应落在越界那一刻而非摊在每次呼吸里。配套的「凭据保护撤回」决策（一个在生效处破坏约束、在不生效处谎报状态的保护，比文档化的缺席更糟）是安全工程里罕见的诚实

## hooks 桥的静默失效实验：bash 拦得住，Bash 一声不吭放行

机制：Claude Code 的 hooks.json 经桥接包可原样拦住 DSH 工具调用（实测返回自设暗号错误），但工具名两边大小写约定不同（CC 首字母大写、DSH 全小写），写成 Bash 的规则整条不触发且无任何告警——装好了、看着在跑、一条没生效。30 个 CC 事件只支持 7 个；CC 的「预先批准」动作在 DSH 侧无对应物。35 个不随装的包 npm latest 标签停旧版，需 @next 后缀才能装到配套版本。

证据：书 §04 hooks 实测段与 @next 版本坑；§99 速查表四

价值：跨 harness 兼容层的教科书级陷阱样本：语法兼容 + 语义（命名约定）不兼容 = 静默失效，比报错更危险。对做兼容层的工程师，「验证桥真的拦住了一次」应写进迁移 checklist

## 验证确认：书标注的三处文档-代码不一致至今仍在仓库里

机制：（1）AGENTS.md:100 与 vendor/README.md:34 声明 vendored 包 `private: true`，实测 9 个 vendor/*/package.json 全部没有 private 字段（且书查证 9 包全发到了 npm）。（2）创造模式随包 SKILL.md（apps/cli/config/agent-presets/cordis/skills/{editing-cordis-compositions,cordis-plugin-development}/SKILL.md）仍引用不存在的 cordis_inspect、cordis_mount、cordis_unmount，实际注册的是 7 个新名字——这份文件是喂给模型的，骗的是模型不是人。（3）文档写自指工具 5 个、运行时 7 个。

证据：本次验证：grep AGENTS.md:100 / vendor/README.md:34 命中 private: true 声明；python 读 9 个 vendor package.json 均无 private 字段；grep SKILL.md 得 cordis_inspect(1)/cordis_mount(2)/cordis_unmount(1)，grep packages 实际注册名 7 个

价值：书的核心可信度检验通过：其余全部可验数字（12,293 commits、683/11/4 篇、27 道门禁、219/184 invariant、reflect.ts:290、44 事件类型、preset 行数、178 tests 原文）逐项与仓库现状吻合。也暴露一个共性教训：模型可见文件（SKILL.md）的名词漂移比人类文档漂移严重一档，值得单独设门禁

## tradeoffs
- 用户视角天然缺失的主题（工程分析必须补上）：agent-loop 源码机制与扩展点契约（waterfall next() 语义、registrations-as-effects、disposer 倒序回收）；测试基建全貌（keyless snapshot replay 管线、test:coverage per-file 100% 门禁的真实维护成本、fixture 跨平台策略、record/replay 假模型）；类型系统纪律（Branded 跨界 id、erasable syntax、typert 类型图生成与前后端契约的活注册表）；会话事件的 required-on-read/ignorable 版本机制；capability seam 三角色的包组织与 verify-cordis-config 强制；defensive-patterns 文档所覆盖的生命周期/并发/teardown 深水区
- 书只能观察制度的产出（683 篇笔记、门禁数量），无法评估制度的执行成本与假阳性率——27 道门禁对开发节奏的真实摩擦、100% 覆盖率门禁诱发的凑数测试风险，这些要从 PR 历史和被豁免记录里才能读出
- 全书实测集中在最小任务（3-4 个小文件），缺少大仓库、长会话、真实并发场景的数据：压缩触发后的行为、上下文顶满时的裁剪质量、多会话并发的资源表现全部标注未实测
- 作者与生态利益相关（自维护 57 个 skill 的池子，DSH 兼容其资产），对 skill 层的评价（「最舒服的一格」「净赚」）应打个折扣读；对插件层「一辈子不会自己动手」的自陈也意味着插件开发体验的评价全部来自文档而非实践
- 时效锁死在 rc.6 快照：书自己声明保质期以小时计、「照着核不照着抄」，其中价格表（8 月 17 日改分时计价）、star 数、生态数字在引用时必须重取
- 书的叙事框架（赌局、代价清单）为可读性做了压缩，工程决策引用时需要回到原始笔记：书转述的十一篇被否提案均为二手转译，关键判词（如「一个承担安全不变量的依赖必须有被证明的采用度」）应回 .agents/notes/rejected/ 核对原文再引用

## learnables
- 首轮成本结构可直接引用：工具说明书 47% + skill 目录 45% + 系统提示词 6%，用户输入 0.2%（29/13,838 token）；skill 池使开机成本 +82%，且每新会话、每个子代理各付一次
- 缓存实测三连：命中数全是 64 的整数倍（DeepSeek 64-token 存储单元被本机验出）；跨进程隔 2 分 21 秒重跑命中 13,824/13,838；flash 命中价 1/50、pro 1/120——但落到总账只省 3.55 倍，因为输出不打折，「省 50 倍」是单价不是总账
- PTC 对照可引用为反直觉案例：同模型同任务，PTC 慢 14 倍（305.9s vs 21.9s）、输出 12 倍（76% thinking）、首轮输入反多 9%；省的是中间结果（15 次内部派发的输出从不进上下文），不省工具定义
- 自造工具的行为比例：19 步中 14 步自省（24 次调用中 20 次在读自身类型声明和运行时），真正写码挂载只占 4 次——「查着写 vs 凭印象写」的定量刻画
- 44 种事件仅 3 种模型可见（user/assistant/tool_result）；一句话任务 44 行日志、echo 任务 35 条记录——可审计性的字面价格
- 129 行插件清单构成整个 agent（含主循环、UI 全部 27 行），24 处出处标记、25 行 disabled；运行时 133 个插件，设置页可配 3 个——「一切皆插件」与「一切皆你能碰的插件」的落差
- AI 建库的量化指纹：64 天 12,293 commits（日均 192，峰值 887/天 + 同日 47 篇设计笔记）；分支前缀 codex/ 203 次、worktree/ 210 次；markdown 2,355 > TypeScript 2,319 个文件；专门的「修剪思维链泄漏」工具第八类清理英文文档里漏出的中文词
- 制度数字：683 篇设计笔记（505 implemented / 142 archived / 25 proposed / 11 rejected），rejected 只在「还能拦住一个诱人的错误」时保留；219 包全带 invariant.ts，184 个空实现须署名说明为何无可查；每包 README 强制 KV Cache effect 段（215/219 填写，4 个白名单豁免且理由被脚本核验）
- harness 差异的外部锚点：Composio 固定 V4-Flash 换 8 个 harness 跑 240 次，通过率 46.7%→66.7%，每次成功成本差 7 倍——「模型一个字没改，7 个任务成败只取决于 harness」
- 工程可用的坑清单：npx 按命令原文缓存（三种写法 = 三份 342MB）；网页版点一下模型下拉会静默覆盖所有 CLI 任务的模型选择（3 倍差价）；上下文进度条按 4 char/token 估算而中文实测 1.71，显示 40% 可能实际 90%；Windows 文件夹选择器截断低字节为零的汉字（「一」「开」「最」等 13 个，#151）
- 压缩省钱的反直觉结论（被否方案）：明知摘要器不调工具也要原样带上两万字符工具说明书，因为它是被缓存序列的一部分，少传反而更贵——KV cache 前缀完整性压倒直觉裁剪

## questionable
- 「四注赌局」框架整体站得住，但第二注（可审计 vs 磁盘）的对立面选错了：真正的代价不是磁盘（打包后一次会话省六成），而是架构自由度——「每个请求是日志的纯函数」这条不变式否决了 PTC 常驻内核、跨调用状态、流式增量等一整类优化路径，书在 §14 点到（拒绝共享状态）但没算这笔机会成本的全账
- 「模型公司下场是为了不把模型好不好用的一半交出去」（第四注）成立但不完整：极简模式同时是 RL 训练环境（书只说「跑分」）；harness 归一化对模型公司的价值还包括训练-推理一致性和数据回流，这是订阅制工具做不到的，书的用户视角看不到这层动机
- PTC 慢 14 倍的数字不可直接引用为普适结论——书自己反复限定（单次、无重复测量、3 个小文件的最小任务），但读者极易摘出「实测 PTC 慢 14 倍」传播；工程引用时必须带上「小任务、中间产物趋零」这个使 PTC 必输的前提条件
- 「没有特权内核」的验证只到配置格式平级（agent-loop 与 timer 同格式可 disabled），书承认没实跑「关掉主循环会怎样」；从 cordis PENDING 语义推断，结果大概率是静默挂起——宣言在配置层为真，在故障体验层「可替换」与「可安全替换」是两回事，书未做此区分
- 「它没有读懂 Claude Code，只是恰好翻同一个抽屉」（~/.agents/skills 是公共约定）——书自己给了正确修正，但前文「零配置端走 57 个 skill」的叙事强度容易让读者记住错误版本；同理 hooks 桥「30 事件支持 7 个」是包的自述，书标注未核对，引用时应降级为二手
- 「崔添翼在 Jane Street 主要写 OCaml」是书作者自己标注的推断而非事实；「Claude Code 泄漏事件触发 DeepSeek 建 harness 团队」的因果线作者也明确声明是自己连的——两条都不能当结论引用
- 分叉是否回滚已改文件、Ralph 循环全套、schedule 八行接线、装第三方插件完整链路——书全部诚实标注未实跑；这些恰是工程师最该自己补测的路径，不能把书的「来自源码和文档」当实测证据
- 书把「订阅默认拦你、API key 默认放行」说成结构性心理差异是对的，但对无人值守场景的成本风险只字未提护栏方案（无预算上限、无告警、账单一直涨）——对要把 DSH 接进自动化的团队这是必须补的运维缺口
