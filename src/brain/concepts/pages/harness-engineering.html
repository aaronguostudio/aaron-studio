Pattern Atlas 07 / Artificial intelligence systems

Working vocabulary · emerging practice

Harness
Engineering

模型提供能力；Harness 把任务契约、上下文、工具、状态、验证、权限与恢复组织成可靠工作。

这是一个正在成形、尚未完全标准化的工程术语。本页把它定义为：围绕可替换模型，设计使智能体可靠完成真实任务的运行系统。

The durable question

为什么同一个模型，换一个环境，就像换了一个产品？

可靠性经常不只来自模型，而来自模型周围能否观察、行动、验证、限制权限并从失败中恢复的系统。

Model only

补丁存在

智能体找到一个看似相关的文件，修改代码，然后用流畅总结宣布完成。真实故障路径、回归与副作用仍然未知。

Model + harness

结果有证据

任务契约定义完成；环境让工作可观察；验证器检查真实结果；权限与恢复把失败控制在边界内。

03 · Mental model

机床提供能力，工装保证结果

高性能数控机床

像模型：可以根据输入推理、选择策略并产生复杂动作。更强的机床能加工更多形状，但不会自己定义“合格”。

图纸、夹具、量规与防护

像 Harness：图纸是任务契约，夹具是上下文与环境，量规是验证，防护是权限，批次记录与复位程序是状态和恢复。

04 · Concept neighbors

不是所有 Agent 基础设施都是一回事

Instruction technique

Prompt Engineering

改善当次运行怎样表达意图；不负责完整任务生命周期。

Subsystem practice

Context Engineering

管理模型看见什么；是 Harness 的核心层，但不是全部。

Runtime artifact

Agent Harness

实际调用模型、路由工具并维护循环的系统；Engineering 是构建它的实践。

Toolkit

Agent Framework

提供通用零件；不等于已经拥有任务契约、证据、权限和恢复。

Integration protocol

Model Context Protocol

连接工具与上下文；不决定何时完成、谁有权限或怎样恢复。

Measurement

Evaluation Harness

运行并评分受控任务；生产 Agent Harness 负责真实工作。

Runtime guarantee

Durable Execution

为检查点、重试和恢复提供底层保证。

Permission model

Capability Security

只授予任务所需的最小能力，限制错误影响范围。

Framework 给你零件。Harness 是运行产物。Harness Engineering 是设计保证的实践。

  • Prompt 表达意图；Contract 定义可以验证的结果。
  • Session 是持久事件史；Context 是此刻选择的工作集。
  • 工具扩大行动力；验证与权限让行动力变得可靠。
  • “调用成功”不等于“业务结果成功”。
  • 恢复必须理解副作用，而不能只盲目重跑。
  • Harness 也会腐烂：需要版本化、评估和删掉过时假设。
